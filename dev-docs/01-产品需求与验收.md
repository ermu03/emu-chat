# 产品需求与验收标准

状态：MVP 已批准实现基线
更新时间：2026-09-19

本文描述产品行为和后续验收标准。Gemini 本轮只写代码与测试文件，不运行任何验收。

## 1. 主要用户流程

### 1.1 打开与连接

1. 用户在服务器或同一可信 LAN 的手机/电脑浏览器中打开 `http://<server-ip>:<port>`。
2. 页面读取 `GET /api/v1/status`，分别显示 emu-chat、SQLite 和 Hermes 状态。
3. Hermes 不可用、鉴权失败或能力不兼容时，不显示伪造的空会话；显示原因与“重新检查”动作。
4. 普通 HTTP 下若 Service Worker/PWA 安装不可用，应用仍作为普通响应式网页完整工作，并显示非阻塞说明。

### 1.2 浏览和继续会话

1. 顶层列表只请求 `default` profile、`source=api_server` 的 root/human sessions。
2. 选择会话后，页面读取 Hermes 当前 effective/resumable segment 的消息。
3. 历史区固定提示：“当前显示可继续的会话段；更早的压缩段可能未展开。”
4. 发送时只提交新输入和明确 `session_id`，不从浏览器重传完整历史，也不发送 `X-Hermes-Session-Key`。
5. 终态后后端重新读取 messages；若 Hermes 返回新的 effective id，原子更新同一本地 conversation 映射。

### 1.3 草稿、发送和排队

1. 输入始终先成为当前会话草稿，并持久化到 emu-chat SQLite。
2. Hermes 健康且会话可写时，用户点击发送：后端把草稿原子转换成 queue item，清空草稿，并返回 operation。
3. 当前无运行且全局 slot 可用时立即 dispatch；否则保持 FIFO `queued`。
4. Hermes 不健康时发送按钮禁用，草稿仍可编辑/保存；连接恢复后不会自动发送，用户必须再次点击。
5. 只有 `completed` 且消息对账成功才自动发送下一条。
6. `failed`、`partial`、`cancelled`、`interrupted` 或对账歧义后保留后续项并暂停；用户可编辑/取消未发送项，或明确“继续队列”。

### 1.4 实时运行和 approval

1. 后端通过 `/v1/runs` 创建 run，并为每个 run 建立唯一上游 SSE 订阅。
2. 页面显示文本 delta、通用工具、reasoning、subagent、approval 和终态；临时事件不写入历史表。
3. approval 只提供“拒绝”和“允许一次”。页面只发送上游当前事件声明且属于 `deny|once` 的 choice，并带 request id（若事件提供）。
4. 运行停止后以 Hermes status 为准；stop HTTP 成功只表示正在停止。

### 1.5 刷新、断线和重启

1. 浏览器刷新或标签页断开不创建新 run、不取消 Hermes run。
2. 重连先读取 run snapshot，再订阅 emu-chat SSE。
3. emu-chat 进程重启会丢失临时事件；已有 `run_id` 时只查询 status/messages，绝不重发输入。
4. 如果只能恢复最终状态，页面显示“最终状态已恢复，部分过程事件不可恢复”。

### 1.6 会话生命周期

- 新建：创建 Hermes session 后建立本地引用。
- 重置：停止/收尾当前 run 后创建全新 session；旧会话保留。
- 分支：调用 Hermes fork；不在本地复制 transcript。
- 重命名/置顶：直接写 Hermes，成功后重读。
- 删除：执行真实 Hermes segment DELETE，确认框必须说明 delegate children、orphan children 和不联动资源。
- 不提供归档、恢复、隐藏操作。

## 2. 功能需求与验收

### 2.1 访问、布局和安全渲染

| ID | 要求 | 后续验收 |
| --- | --- | --- |
| WEB-01 | LAN HTTP | 服务可配置端口并默认绑定 `0.0.0.0`；手机通过服务器 LAN IP 可访问；无登录页 |
| WEB-02 | 响应式 | 320px、768px、1280px 无关键控件遮挡；会话抽屉、输入、停止、队列可触摸 |
| WEB-03 | PWA 降级 | 无 secure context 时不报错、不反复注册 SW；普通 Web 功能完整且说明安装能力受限 |
| RENDER-01 | Markdown/GFM/LaTeX/代码 | 表格、任务列表（仅展示）、KaTeX、代码高亮和复制工作；长内容不撑破布局 |
| RENDER-02 | 安全输出 | raw HTML 默认不执行；`script`、危险 URL、iframe/object 被拒绝；模型文本从不进入未净化 `innerHTML` |
| RENDER-03 | 流式内容 | 未闭合 fenced code/数学标记不会破坏布局；终态后完整重渲染稳定 |

### 2.2 连接和会话

| ID | 要求 | 后续验收 |
| --- | --- | --- |
| CONN-01 | 状态区分 | `healthy/degraded/unavailable/auth_failed/incompatible` 有不同文案和可用动作；读取失败不显示为空列表 |
| HIST-01 | 列表范围 | 上游请求固定 `source=api_server`；不把 children 或其他 source 作为顶层写入会话 |
| HIST-02 | 消息读取 | 只显示 Hermes `data` 投影和响应 effective `session_id`；不读取本地 transcript |
| HIST-03 | 搜索 | 精确 ID 与 exact-title 能导航；UI 明示“不搜索消息正文” |
| HIST-04 | 历史范围 | 固定显示当前 segment 范围提示；不遍历 parent 拼接 compression/branch/delegate |
| HIST-05 | 有限工作流投影 | 历史只渲染 `/messages` 字段；临时 SSE 不在刷新后伪装成完整 workflow 历史 |

### 2.3 草稿、队列和并发

| ID | 要求 | 后续验收 |
| --- | --- | --- |
| DRAFT-01 | 草稿持久化 | 每会话最多一个草稿；刷新后恢复；草稿不属于 transcript |
| DRAFT-02 | 离线规则 | Hermes 非 healthy 时不能创建 queued item；草稿不清空；恢复后不自动发送 |
| QUEUE-01 | FIFO | 每会话 `fifo_seq` 唯一、单调；只有队首可 dispatch |
| QUEUE-02 | 可编辑范围 | 只允许编辑/取消 `queued`；已有提交尝试的项不可编辑 |
| QUEUE-03 | 暂停 | 非成功终态保留后续项并把 conversation queue 标为 paused；只有明确 resume 才继续 |
| CONC-01 | 并发 1 | 任意时刻数据库层最多一个全局 active dispatch/run，且每会话最多一个 |
| CONC-02 | 多标签页 | 重复点击或两个标签页发送不会产生重复 operation/run；冲突端返回 `LOCAL_CONFLICT` |

### 2.4 Run 与恢复

| ID | 要求 | 后续验收 |
| --- | --- | --- |
| RUN-01 | 幂等提交 | operation 创建时固定 key；无 run id 的不确定提交只在 86400 秒内用同 key/body/session 恢复 |
| RUN-02 | 202 语义 | 202 只标记 accepted，不清除恢复正文，不显示为已写入历史 |
| RUN-03 | 已有 run id | 刷新、失败、中断、404 或后端重启均不自动 POST 原输入，也无“一键重放”按钮 |
| RUN-04 | 实时事件 | delta、tool、reasoning、subagent、approval 和终态可显示；未知合法事件安全忽略并计数 |
| RUN-05 | 单上游订阅 | 同一 Hermes run 最多一个上游 events consumer，多个浏览器只订阅本地 fan-out |
| RUN-06 | 终态对账 | `completed` 后需 status + messages 成功才标记 done、清恢复正文并自动继续队列 |
| RUN-07 | 部分/中断 | 保留原生 status 与 `partial`；`interrupted` 可由 status 恢复，不等待同名 SSE |
| RUN-08 | 恢复副本 | 非成功/歧义结果显示 7 天到期时间；只可复制为新草稿或丢弃；到期后清正文并保留过期标记 |
| RUN-09 | Stop | stop 后显示 stopping，以 Hermes 终态结束；后续队列保持暂停 |

### 2.5 工具、checklist 与 approval

| ID | 要求 | 后续验收 |
| --- | --- | --- |
| TOOL-01 | 通用工具状态 | 显示工具名、开始/完成/失败和安全 preview；不把 preview 当完整结果 |
| TOOL-02 | checklist 降级 | `todo_list` 是普通工具卡；Markdown checkbox 只是内容；不显示权威任务进度百分比 |
| SUB-01 | 子 Agent | 活动期显示 start/complete 摘要；不重建或持久化 subagent 树 |
| APPR-01 | 等待与响应 | 显示 approval 请求；只允许 `once`、`deny`；没有自动批准、session、always |
| APPR-02 | 竞态 | 已失效或重复响应显示冲突并刷新 run，不猜测已执行 |

### 2.6 生命周期和元数据

| ID | 要求 | 后续验收 |
| --- | --- | --- |
| LIFE-01 | 新建/重置/分支 | 三者是不同动作和确认文案；失败不改变当前映射 |
| META-01 | 权威字段 | title/pinned 只写 Hermes；本地只存 tags/custom_order；无本地 title/hidden/archive mirror |
| LIFE-02 | 无归档 UI | 路由、菜单、页面和内部 API 均不出现 archive/restore 操作 |
| DEL-01 | 真实范围 | 确认框说明当前 segment + delegate children；branch/compression children 可能 orphan |
| DEL-02 | 删除门禁 | 当前 run 未收尾或 Hermes 全局 active agent 非零时不发 DELETE；不提供 force |
| DEL-03 | 删除一致性 | Hermes 成功或独立 GET 确认不存在后才清理本地；超时/5xx/未确认 404 保留 pending |
| DEL-04 | 非联动资源 | 明示 memory、附件、artifact、工具文件不随 transcript 删除 |

## 3. 错误与文案原则

- “请求已发送”不等于“成功”；“run 已接纳”不等于“输入已持久化”。
- “Hermes 读取失败”不等于“没有会话”。
- “过程事件缺失”不等于“run 失败”。
- 错误响应和日志不得包含 Bearer、provider key、cookie、服务器绝对路径或未经脱敏的命令/工具输出。
- 每个可操作错误都给出唯一、符合状态机的动作；不得提供可能重复执行原输入的通用“重试”。

## 4. 首版明确不承诺

- 跨 compression 完整 transcript、全文搜索、历史完整 workflow/checklist/subagent timeline；
- replay Hermes 未持久化的过程事件；
- archive/restore、附件/图片、通知、语音、steer；
- OpenAI-compatible API、离线历史或公网安全；
- 对已有 `run_id` 的原输入自动或一键重放。
