# emu-chat 项目章程与范围

状态：MVP 已批准实现基线
更新时间：2026-09-19

## 1. 产品定位

emu-chat 是面向单用户的 Hermes Agent Web 工作台，目标是在桌面和手机浏览器中提供轻量、清晰、易维护的聊天与运行控制界面。

Hermes 负责 Agent、模型、工具、记忆、压缩和会话谱系；emu-chat 只负责浏览器 UI、输入草稿、发送队列、运行协调、断线恢复和少量本地 UI 元数据。它不是新的 Agent runtime，也不是 Hermes transcript 的第二份数据库。

第一版运行在用户自己的服务器上，通过可信局域网 HTTP 访问。它不提供公网安全、登录、HTTPS 或多用户能力。

## 2. 不可违反的数据边界

### 2.1 Hermes 是唯一历史来源

- Hermes `state.db` 及其原生 API 是消息、工具结果、会话谱系和已持久化 transcript 的唯一权威。
- emu-chat 不直接打开、读写或迁移 Hermes SQLite，不 import Hermes Python 包。
- emu-chat 不保存用户/助手消息、工具结果、完整 run 事件或 workflow timeline 的长期副本。
- 浏览器只访问 emu-chat；Hermes Bearer key 只存在于 emu-chat 后端配置中。

### 2.2 emu-chat 可保存的最小状态

- 本地 conversation id 到当前 Hermes effective `session_id` 的映射；
- 本地 `tags`、`custom_order` 和界面偏好；
- 每个会话的草稿；
- 未发送队列、operation、幂等键、run 控制状态和数据库租约；
- Hermes 尚未安全收尾时的有界恢复正文；
- 活动 run 的内存事件环形缓冲。

恢复正文和事件缓冲不是历史库。成功完成并对账后立即清除正文；失败、取消、中断或歧义结果的恢复正文最多保存 7 天。事件缓冲在进程重启后可以丢失，UI 必须明确说明。

### 2.3 上游与本地元数据

- Hermes 是 `title`、`pinned`、`hidden`、`archived` 的唯一权威。
- MVP 只允许从 emu-chat 修改 Hermes title 和 pinned。
- hidden 只读取，不提供隐藏/恢复 UI；archive/restore 完全不在 MVP。
- emu-chat 本地只写 `tags` 与 `custom_order`，不建立同名上游字段镜像或 override。

## 4. MVP（P0）范围

### 4.1 访问与界面

- Fastify 服务绑定 `0.0.0.0`，手机和桌面通过可信 LAN HTTP 使用；
- 320px、768px、1280px 响应式布局；
- 普通 Web 应用始终可用；manifest 可以提供，但 LAN HTTP 下不保证 Service Worker、安装型 PWA 或离线壳；
- Markdown/GFM、KaTeX、代码高亮、复制和严格安全渲染；
- 明确展示 emu-chat/Hermes 连接状态和能力降级。

### 4.2 会话与历史

- 固定 `default` profile；顶层列表仅包含 Hermes `source=api_server` 的 root/human sessions；
- 按 Hermes 分页读取列表、详情和消息；
- 精确 session ID 和 exact-title 搜索；不做全文搜索；
- 只显示当前 effective/resumable segment，并提示更早 compression segment 未展开；
- 历史中只展示 Hermes `/messages` 已持久化的安全字段投影；不声称完整 run/workflow/checklist 时间线。

### 4.3 实时运行、approval 与队列

- UI 执行路径只使用 Hermes `/v1/runs`；不做任何静默 fallback；
- 实时显示文本 delta、通用工具、reasoning、subagent、approval 和终态；
- `todo_list` 只作为普通工具状态，不解析权威 checklist；
- approval 支持 `once` 与 `deny`，不自动批准；
- 每条消息是独立 operation，FIFO 排队；全局并发 1、每会话并发 1；
- 后端保持每个 Hermes run 唯一上游 SSE 订阅，再向浏览器 fan-out；
- 浏览器刷新/短断线不重复提交；后端重启后以 Hermes status/messages 恢复最终状态；
- 非成功终态保留后续队列并暂停，用户明确继续后才发送下一项。

### 4.4 草稿和恢复正文

- Hermes 不健康时仍可保存/编辑草稿，但发送请求必须失败且草稿保持不变；
- 连接恢复不会自动把草稿入队；
- 无 `run_id` 的不确定提交可在 86400 秒内用同 key、同 payload、同 session id 有界重试；
- 一旦有 `run_id`，绝不自动重发原输入；失败类结果最多保留 7 天恢复副本，只可复制为新草稿或丢弃。

### 4.5 会话生命周期

- 新建、继续、重置、分支；
- Hermes title 重命名、pinned 更新；
- 删除当前 segment，并明确 delegate child 级联及 branch/compression child orphan 影响；
- 删除前先处理当前 emu-chat run，并在 Hermes 全局仍有 active agent 时保守拒绝；
- 删除成功或经独立只读对账确认不存在后，才清理本地映射。

## 5. MVP 明确不包含

- archive、unarchive、归档列表或恢复；
- transcript 全文搜索、跨 compression 完整时间线；
- 权威 checklist、完整历史 run/workflow/subagent timeline；
- 图片/附件输入、通知、语音、跨标签页 `BroadcastChannel`；
- steer、session/always approval；
- OpenAI-compatible 对外 API 或 UI fallback；
- 离线历史、离线推理、多租户、认证、HTTPS、反向代理、公网部署；
- 修改 Hermes 源码或依赖 Dashboard 未运行接口。

## 6. P1/P2

P1 候选：附件/图片、通知、即时多标签页同步、完整 approval 管理、主题/国际化、在 Hermes 正式支持后加入全文搜索/完整时间线/归档。

P2 候选：语音、多租户/RBAC、Tauri、云同步、第三方消息平台和插件市场。
