# MVP 决策记录（Q-00～Q-18）

状态：已批准，实现时不得重新选择
更新时间：2026-09-19

文件名为兼容既有链接保留；本文件中的决策均已关闭。未来改变任一项，必须先更新本文件及受影响的 ADR/契约，不能由实现模型自行调整。

## Q-00：跨 compression 的完整可视历史

决定：MVP 只显示 Hermes `/messages` 返回的当前 effective/resumable segment，并明确提示“更早的压缩段未在当前视图展开”。

不得遍历 `parent_session_id` 拼接历史。跨 compression 的完整逻辑时间线是未来能力，且只能由 Hermes 提供正式只读投影。

## Q-01：搜索范围

决定：MVP 只支持精确 Hermes session ID 查询和 Hermes exact-title 查询。当前页的即时过滤可以作为纯 UI 辅助，但不得称为全文搜索。

不实现 transcript 全文搜索，不在 emu-chat 建立消息索引或副本。

## Q-02：checklist/todo

决定：MVP 只显示当前活动 run 的通用工具和子 Agent 事件，包括 `todo_list` 作为普通工具的开始、完成或失败；不提供权威 checklist 条目状态。

Markdown task list 只按内容渲染，不转换成运行状态；截断的 tool preview 也不得被解析成 checklist。

## Q-03：`X-Hermes-Session-Key`

决定：MVP 不发送 `X-Hermes-Session-Key`，所有执行都使用明确的 Hermes `session_id`。

长期记忆/affinity scope 留作未来单独设计，不与 transcript id 混用。

## Q-04：非成功终态后的队列

决定：`failed`、`partial=true`、`cancelled`、`interrupted` 或结果无法对账后，保留所有尚未发送项并暂停该会话队列。

只有用户看过状态并明确点击“继续队列”后，协调器才允许发送下一项；用户在暂停期间仍可编辑或取消尚未发送项。

## Q-05：删除范围

决定：MVP 只提供 Hermes 当前真实 DELETE 语义：删除指定 segment 及 Hermes 定义的 delegate children；branch/compression children 可能变为 orphan。

UI 必须在确认框中写明上述影响，不提供“删除整个谱系/子树”。长期记忆、附件、工具产物和外部文件不随之删除。

## Q-06：首发访问方式

决定：第一版绑定 `0.0.0.0`，允许手机通过可信局域网使用普通 HTTP 访问。MVP 不做 emu-chat 登录、HTTPS、反向代理或公网部署安全保证。

这是明确接受风险的开发/自用部署，只能放在可信 LAN。Hermes 仍只监听 `127.0.0.1:8642`，Bearer key 仍不得进入浏览器。普通 LAN HTTP 不是 secure context，因此 Service Worker、安装型 PWA 和离线壳不作为首发保证；页面必须在不支持时退化为普通响应式 Web 应用并显示说明。

## Q-07：Hermes 离线时的输入

决定：允许保存和编辑草稿，但离线时不能把草稿转换成 `queued`，也不能在连接恢复后自动发送。

Hermes 恢复健康后，用户必须再次明确点击发送/入队。

## Q-08：并发

决定：MVP 固定全局最多 1 个未终态/未完成对账的 run，每个会话最多 1 个。此值在 MVP 不做 UI 配置。

## Q-09：approval

决定：MVP 必须支持等待状态、拒绝和单次允许，对应上游 choice `deny` 与 `once`。即便 Hermes 事件提供 `session`/`always`，MVP UI 也不展示、不发送。

approval 不得自动通过。完整授权管理、会话级或永久授权属于 P1。

## Q-10：附件、通知和多标签页

决定：后端租约、防重复提交、刷新后状态一致性为 P0；`BroadcastChannel` 即时同步、图片/附件、浏览器通知为 P1；语音为 P2。

MVP 多标签页通过后端权威状态和 SSE 最终一致，不要求标签页之间直接广播。

## Q-11：技术基线

决定：采用单仓库 TypeScript 全栈：React + Vite 前端、Fastify 长驻 Node 后端、SQLite、本地 REST/JSON + SSE。生产部署是一个长驻 Node 服务，不使用 Next.js、Python 中间层、serverless 或 Edge runtime。

精确版本范围和目录见 `11-Gemini编码交接基线.md`。

## Q-12：Hermes 源码修改与验证权限

决定：当前阶段禁止修改任何 Hermes 源码或运行副本。Gemini 只编写 emu-chat 代码，不做真实 Hermes 联调，也不得运行任何测试、build、lint、typecheck 或服务进程。

可以根据批准文档编写测试文件/fake fixture，但只能静态交付，必须明确“未运行”。

## Q-13：会话来源和 profile

决定：MVP 固定 `default` profile，只把 Hermes `source=api_server` 且列表默认返回的 root/human sessions 作为顶层会话。

delegate/compression children 不独立显示为顶层项；其他来源不提供写入或筛选 UI，未来可增加只读入口。

## Q-14：202、输入持久化与恢复副本

决定：Hermes `202 + run_id` 只表示 run 已接纳，不表示用户输入已写入 transcript。

执行规则固定如下：

1. 在向 Hermes 提交前，emu-chat 原子保存 operation、稳定 idempotency key 和输入正文。
2. 如果提交结果不确定且尚无 `run_id`，只可在 Hermes 声明的 86400 秒幂等窗口内，以完全相同的 key、payload 和 session id 有界重试。
3. 一旦取得 `run_id`，无论之后是失败、取消、中断、404 或重启，绝不自动重新 POST 原输入，也不提供“一键重放原消息”。
4. `completed` 且 session messages 成功对账后，立即清除恢复正文，只保留 hash、字节数和控制状态。
5. `failed/cancelled/interrupted` 或接纳/持久化仍有歧义时，将会话队列暂停；恢复正文从进入 `paused/review_required/rejected` 起最多保留 7 天。UI 显示到期时间，只允许“复制为新草稿”或“丢弃恢复副本”，并警告复制后重新发送可能重复。
6. 7 天到期后自动清除正文并记录 `payload_expired_at`；不得继续把它当历史或搜索来源。过期前不得静默清除。

当前不修改 Hermes，也不通过正文相等猜测 message/run 关联。

## Q-15：元数据权威

决定：Hermes 是 `title`、`pinned`、`hidden`、`archived` 的唯一权威；emu-chat 不建立这些字段的本地同名镜像或 override。

MVP 可写的上游元数据只有 title 和 pinned。hidden 只按 Hermes 返回值读取，不提供隐藏/恢复 UI；archive/restore 由 Q-16 排除。emu-chat 本地只保存 `tags` 与 `custom_order`。

## Q-16：归档与恢复

决定：MVP 不提供 archive、unarchive、归档列表或恢复 UI，也不把归档作为删除替代品。

原因是当前 Hermes 列表端点无法发现全部 archived sessions，且 archive 会影响 compression lineage。未来只有在 Hermes 正式提供归档筛选/发现契约后再设计；当前阶段不得修改 Hermes 补齐。

## Q-17：OpenAI-compatible 的含义

决定：emu-chat 聊天 UI 只使用 Hermes 自定义 `/v1/runs` 主通道。它不得被描述为 OpenAI 标准接口，也不得静默 fallback 到 `/v1/chat/completions` 或 `/v1/responses`。

MVP 不对外暴露 OpenAI-compatible API。Hermes 已有兼容端点只作为能力说明和未来独立兼容项，不进入首发功能或验收。

## Q-18：历史工作流详情

决定：MVP 历史区只显示当前 effective/resumable segment 中 Hermes `/messages` 已持久化的字段投影：role、content、tool call id、tool calls、tool name、timestamp、finish reason、reasoning/reasoning content 和 display kind。

活动 run 可显示临时 delta、通用工具、reasoning、subagent 和 approval 事件；刷新或后端重启后若事件丢失，只显示“部分过程事件不可恢复”。MVP 不承诺完整历史 run、workflow timeline、subagent 树、工具参数历史或 checklist timeline，也不长期保存 SSE 来补齐。
