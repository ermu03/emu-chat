# emu-chat 页面信息架构与关键状态稿

状态：MVP 已批准实现基线
更新时间：2026-09-19

本文固定页面职责、主要交互和状态文案。具体颜色、字体和间距可调整，但实现不得删除关键状态、合并不同语义或加入 MVP 外功能。

## 1. SPA 路由

| 路由 | 页面 |
| --- | --- |
| `/` | 应用壳；未选会话时显示欢迎/连接状态 |
| `/c/:conversationId` | 指定 conversation 工作台，可刷新深链 |
| `/settings` | 连接摘要、LAN HTTP/PWA 警告、UI 偏好；不含 Hermes key/URL 编辑 |
| 其他 | 本地 404，返回会话列表入口 |

URL 使用 emu-chat local conversation id，不直接把 Hermes session id 作为主路由。Hermes id 可在详情中查看/复制。

## 2. 桌面布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ 顶栏：emu-chat | Hermes 状态 | LAN HTTP 警告 | 设置             │
├──────────────────┬───────────────────────────────────────────────┤
│ 会话侧栏         │ 会话标题 / pinned / 操作菜单                  │
│ - 新建           ├───────────────────────────────────────────────┤
│ - 精确搜索       │ 当前 segment 范围提示                         │
│ - 会话列表       │                                               │
│ - 加载/错误/空   │ Hermes 历史消息                               │
│                  │ 临时 active-run 消息/工具/approval             │
│                  │                                               │
│                  ├───────────────────────────────────────────────┤
│                  │ 运行栏：状态 / stop / reconcile / 过程缺失     │
│                  ├───────────────────────────────────────────────┤
│                  │ 队列折叠面板：FIFO / pause / recovery          │
│                  ├───────────────────────────────────────────────┤
│                  │ 输入区：draft / 保存状态 / send               │
└──────────────────┴───────────────────────────────────────────────┘
```

侧栏宽度 240–520px，可存 preference。主消息区与输入区不能因长代码/工具参数产生整页横向滚动。

## 3. 手机布局

- 顶栏保留：会话抽屉按钮、截断标题、Hermes 状态、运行状态入口。
- 会话列表使用左侧抽屉；打开后焦点锁定，关闭后焦点返回触发按钮。
- 队列/运行详情使用底部 sheet；stop 和 approval 操作不能藏在仅 hover 菜单。
- 输入区 sticky 在 viewport 底部，适配软键盘和 safe-area。
- 删除/分支等确认使用全屏 dialog；按钮最小触控高度 44px。
- 320px 宽时 title、状态和按钮可以换行，但发送/停止不可被遮挡。

## 4. 顶栏和连接状态

| 后端状态 | 显示 | mutation |
| --- | --- | --- |
| `checking` | “正在检查 Hermes…” | 禁止 send/lifecycle；允许保存 draft |
| `healthy` | 绿色“已连接” | 按各资源状态允许 |
| `degraded` | “能力受限” + 缺失能力 | 禁止受影响动作，不 fallback |
| `unavailable` | “Hermes 不可用” + 重检 | 禁止 send；允许 draft |
| `auth_failed/config_error` | “服务器配置错误” | 禁止全部 Hermes 动作 |
| `incompatible` | “Hermes 协议不兼容” | 禁止全部 Hermes mutation |

连接失败时会话区显示错误卡，而不是“暂无会话”。已有 React state 可保持在屏幕上，但必须加“可能已过期”遮罩，不能表示刚刚成功读取。

顶栏固定显示 LAN HTTP 警告入口；设置页完整说明“无认证、仅可信局域网、勿暴露公网”。

## 5. 会话侧栏

### 5.1 搜索

搜索区明确提供模式选择：

- `精确会话 ID`
- `完整标题`

按钮文案为“精确查找”，下方固定说明“不搜索消息正文”。不使用单一模糊搜索框暗示全文能力。

可以另有“筛选当前已加载列表”的客户端输入，但标签必须是“筛选本页”，只影响当前 data，清空后恢复；不得发消息全文搜索或宣传为全局结果。

### 5.2 列表项

显示 Hermes title、pinned、last active、短 preview，以及本地 tags/queue/run 徽标。hidden 若上游返回，用只读“由 Hermes 隐藏”标记；不提供解除按钮。archive 不显示，也没有归档入口。

本地 queue 徽标：排队数量、运行中、已暂停、人工复核。preview 仅来自当前列表响应，不写 SQLite。

### 5.3 列表状态

- loading：skeleton；
- empty：`当前没有可见的 API Server 会话` + 新建；
- error：错误码对应文案 + 重试；
- exact search no result：`未找到完全匹配的会话`；
- pagination：明确“加载更多”，不无限重复请求。

## 6. 会话头和历史范围

头部显示 title、pinned、tags、Hermes session id（详情中复制）、重命名、置顶、分支、重置、删除。

操作菜单中明确没有 archive/restore/hide。

消息区顶部始终显示范围提示：

> 当前显示 Hermes 可继续的会话段。更早的压缩段可能未在此视图展开。

如果 messages 响应轮换 effective id，提示一次“已切换到 Hermes 当前可继续段”，不把它称为创建新聊天。

## 7. 历史消息与活动投影

### 7.1 历史消息

- 只渲染 `GET messages` 的 `data`；
- user/assistant/tool/system 使用明确视觉角色；
- reasoning 默认折叠并标注为 Hermes 持久字段；
- tool call/result 只展示批准字段和安全文本；长内容折叠；
- Markdown task list 保持普通内容，不加运行状态含义。

### 7.2 活动 run

活动 run 的 delta/tool/reasoning/subagent 卡片放在“实时过程”容器中，与历史消息有视觉边界并标注“临时过程”。

- reconcile 成功后移除临时容器，刷新 Hermes messages；
- `stream.gap`/进程重启后清空不完整 delta，显示“最终状态可恢复，部分过程事件不可恢复”；
- 不把临时工具卡留在刷新后的历史中；
- `todo_list` 卡片只显示工具运行/完成/失败，不解析条目和百分比。

## 8. Draft 与输入区

- 打字后 500ms debounce 保存 draft；切换会话/点击发送前立即 flush。
- 显示 `未保存 / 保存中 / 已保存 / 保存冲突 / emu-chat 连接断开`。
- draft revision 冲突时停止自动覆盖，显示服务器版本与当前编辑内容的选择；MVP 可提供“使用服务器版本”或“以当前内容覆盖（用最新 revision 再提交）”。
- Hermes 非 healthy：编辑和保存仍可用，发送按钮禁用，文案“连接恢复后请手动发送”。
- 当前 run 活跃或全局 slot 忙：发送仍允许，结果进入 FIFO queued。
- conversation queue paused：发送仍允许创建 queued item，但按钮旁显示“将加入已暂停队列，不会自动执行”。
- draft 空白、超过 64KiB、保存中未 flush、delete pending 时发送禁用。

发送操作：先确保最新 draft 保存成功，再生成稳定 `client_request_id` 调用 messages endpoint；响应丢失时用同一 id 重试 Browser API，不能生成第二个 id。

## 9. 运行状态与动作

| 内部条件 | 用户文案 | 允许动作 |
| --- | --- | --- |
| queue `queued` | 等待发送 | 编辑、取消 |
| `dispatching` | 正在提交 | 查看；不重复发送 |
| upstream `queued/running` | 运行中 | 停止 |
| `waiting_for_approval` | 等待确认 | 拒绝、允许一次 |
| `stopping` | 停止中 | 等待/刷新 |
| local `reconciling` | 正在核对结果 | 等待；超时后可重新核对 |
| `completed + reconciled` | 已完成 | 查看历史 |
| `failed + partial` | 部分完成，队列已暂停 | 查看历史、复制恢复正文、继续后续队列 |
| `failed` | 失败，队列已暂停 | 同上 |
| `cancelled` | 已取消，队列已暂停 | 同上 |
| `interrupted` | 已中断，队列已暂停 | 同上 |
| item `rejected` | 提交被拒绝 | 复制为新草稿、丢弃副本 |
| local `review_required` 且有 Hermes run id | 需要人工复核 | 重新核对、复制为新草稿、丢弃副本 |
| local `review_required` 且无 Hermes run id | 无法自动核对是否接纳 | 复制为新草稿、丢弃副本；不得显示重新核对 |
| `events_truncated` | 最终状态已恢复，部分过程缺失 | 刷新历史 |

“重试”这个通用按钮禁止出现。安全动作必须具体命名为“重新核对状态”或“复制为新草稿”。

## 10. Approval 卡片

必须显示：等待确认、redacted command/description（若有）、工具在 Hermes 服务器执行、request id 的短标识、到期信息（若有）。

按钮只有：

- `拒绝` -> `deny`
- `允许一次` -> `once`

即使上游 choices 包含 session/always，前端也不显示。点击后禁用本卡直到响应；409 时显示“请求已失效，正在刷新运行状态”，不显示成功。

## 11. 队列面板

按 fifo seq 展示未完成项：正文预览、状态、创建时间。只有 queued 显示编辑/取消。

暂停 banner 显示具体原因和：

- `继续后续队列`：只发送尚未发送的队首；不重发失败项；
- `查看出错运行`；
- queued 项各自编辑/取消。

`manual_resume_required` 显示：“重新核对已确认本次运行完成；后续排队消息仍未发送。”只有用户点击“继续后续队列”才清除该暂停。

恢复正文卡（paused/review_required/rejected）显示：

- “这不是 Hermes 历史副本，仅用于恢复”；
- 到期绝对时间与剩余时间；
- `复制为新草稿`（二次提示可能重复）；
- `丢弃恢复副本`；
- 过期后显示“恢复副本已过期”，无复制按钮。

## 12. 生命周期 UI

### 新建

无破坏性确认；可选 title。上游成功后打开新 conversation。

### 重置

确认文案：“创建一个新的空 Hermes 会话；当前会话不会删除。”active run 时禁用并引导先停止/收尾。

### 分支

确认文案：“从当前 Hermes 会话创建独立分支；父会话保留。”

### 置顶

帮助文本：“这是 Hermes 元数据，可能影响该压缩链，并可能清除 Hermes hidden 状态。”

### 删除

按钮名固定“删除当前 Hermes 会话段”。dialog 必须完整展示 `05` 的五项影响、expected session id 和不可逆 checkbox。

active run 或全局 active agent 门禁时不显示成功/force；超时显示“删除结果未确认”，conversation 保持可见并标 pending。

## 13. 设置页

只包含：

- emu-chat/database/Hermes 状态与重新检查；
- Hermes 版本和缺失 capability 的安全摘要；
- LAN HTTP 无认证警告；
- 当前浏览器 secure context / Service Worker 可用性；
- theme、sidebar width、send shortcut；
- 产品边界说明（Hermes 是唯一历史，当前 segment，精确搜索）。

不显示或编辑 Hermes base URL、API key、provider key、模型 relay、归档、OpenAI-compatible fallback。

## 14. 可访问性最低要求

- 全部按钮有可见 focus，icon-only 按钮有 aria-label；
- dialog/drawer focus trap 和 Escape 关闭（危险确认提交中除外）；
- 状态不只靠颜色；动态 run 状态使用节制的 `aria-live`，delta 不逐 token 大声播报；
- 键盘可完成发送、停止、queue 编辑/cancel、approval 和 dialog；
- `Enter`/`Mod+Enter` 行为由 preference 决定，Shift+Enter 始终换行。
