# 系统架构与数据边界

状态：MVP 已批准实现基线
更新时间：2026-09-19

## 1. 目标架构

```text
桌面/手机浏览器（可信 LAN，HTTP）
        │ same-origin REST/JSON + SSE
        ▼
emu-chat 长驻 Node/Fastify 服务（0.0.0.0）
        ├── 静态提供 React/Vite Web UI
        ├── Browser API：校验、错误包、SSE fan-out
        ├── Hermes Adapter：Bearer、capabilities、session/run 协议
        ├── Coordinator：草稿、FIFO、全局/会话并发 1、恢复
        └── emu-chat SQLite：最小状态，无 transcript
                 │ Authorization: Bearer API_SERVER_KEY
                 ▼
Hermes Gateway API（仅 127.0.0.1:8642）
        ├── session REST -> Hermes state.db（唯一历史）
        └── /v1/runs -> Agent / model / tools / memory
```

生产部署只有一个长驻 Node 服务进程。前后端代码分层，但不得增加 Python 中间层、serverless worker 或浏览器直连 Hermes 路径。

## 2. 组件责任

### 2.1 React 前端

- 只调用同源 `/api/v1/*`；不接触 Hermes URL、Bearer key 或原始错误。
- 展示从 Hermes 即时读取的会话/消息，以及 emu-chat 的草稿、队列和运行控制状态。
- 临时拼接活动 run 的 delta，但不把它写入 IndexedDB/localStorage 作为历史。
- 任何刷新后的权威历史重新从后端读取。
- 在普通 LAN HTTP 下仍完整作为 Web 应用工作；Service Worker/PWA 安装只是 secure context 下的增强。

### 2.2 Browser API

- 提供稳定的 `/api/v1` 契约和统一安全错误包。
- MVP 没有登录/session 认证；仍拒绝 CORS，且不提供任意 Hermes URL/file proxy。
- 校验所有请求字段、长度、枚举和状态前置条件；未知字段拒绝。
- 把上游错误映射为本地错误码，不直接返回堆栈、绝对路径、Bearer 或原始敏感工具文本。

### 2.3 Hermes Adapter

- base URL 固定为服务端配置，MVP 默认 `http://127.0.0.1:8642`。
- 启动和显式重检时读取 `/health`、`/v1/capabilities`；只调用已批准的 endpoint。
- session 读取固定 `default` profile 与 `source=api_server`；不使用 Dashboard API。
- run 请求不发送 `X-Hermes-Session-Key`，不发送完整历史。
- 严格 allowlist 上游字段；合法未知字段忽略并计数，契约破坏进入 `HERMES_PROTOCOL_ERROR`。

### 2.4 Run/Queue Coordinator

- 数据库层固定全局最多一个 active operation，每个 conversation 最多一个。
- 草稿和 queue item 是不同资源；离线时只允许草稿。
- 每个 operation 在首次创建时生成不可变 idempotency key。
- 对每个 Hermes run 保持且仅保持一个上游 events consumer，再向所有浏览器连接 fan-out。
- 浏览器连接不拥有 run；浏览器断开时后台任务继续。
- 只有 `completed + messages reconciliation` 才释放为成功并自动推进队列。
- 非成功终态暂停 conversation queue；已有 `run_id` 永不重发原输入。

### 2.5 SQLite Repository

- 使用参数化 SQL、显式 migration、事务和 partial unique index 实现不变量。
- 打开 `foreign_keys=ON`、WAL 和 `busy_timeout`。
- repository 是唯一可执行 SQL 的应用层；React、route handler 和 Hermes adapter 不直接查询数据库。
- 精确 DDL、枚举和事务见 `11-Gemini编码交接基线.md`，不得由实现模型另起 schema。

## 3. 数据权威矩阵

| 数据 | 权威来源 | emu-chat 是否持久化 | 说明 |
| --- | --- | --- | --- |
| session 是否存在、source、lineage、message_count | Hermes | 只保存当前引用 | 每次列表/详情重读 |
| title、pinned、hidden、archived | Hermes | 否 | MVP 只写 title/pinned；无 archive/hidden UI |
| 消息、reasoning、tool call/result | Hermes | 否 | 只读投影，不建 messages 表 |
| 历史 run/workflow/checklist | Hermes 能提供多少就显示多少 | 否 | MVP 不承诺完整投影 |
| 当前 effective `session_id` | Hermes | 是，作为引用 | 终态后根据 messages 响应更新 |
| tags、custom_order | emu-chat | 是 | 不回写 Hermes |
| draft | emu-chat | 是 | 每 conversation 至多一个；不是消息 |
| queued/dispatching input | emu-chat | 是 | 发送与恢复所必需；不是历史 |
| accepted run 的恢复正文 | emu-chat | 有界 | 成功对账清除；非成功最多 7 天 |
| operation/run/lease 状态 | emu-chat + Hermes status | 是 | 本地/上游状态分列 |
| 活动期 delta/tool events | 内存 | 否 | 有界环形缓冲；重启可丢失 |

## 4. 本地持久化模型

### 4.1 `conversations`

只保存本地稳定 id、当前 Hermes session 引用、tags/custom order、队列暂停状态和对账时间。禁止出现 `title_override`、`pinned_ui`、`hidden_ui`、`archived_ui` 或消息摘要正文。

Hermes 列表项在返回浏览器前惰性建立/更新引用；`hermes_session_id` 唯一。压缩轮换时保持 `id` 不变，只更新该引用。

### 4.2 `drafts`

每个 conversation 固定一行：`content`、`revision`、更新时间。空内容仍保留该行和 revision，避免发送或清空后丢失 CAS 版本。草稿可在 Hermes 离线时保存，但只有健康检查为 `healthy` 且 conversation 无状态冲突时才能转换为 queue item。

### 4.3 `queue_items`

每条用户发送意图一行，包含 FIFO 序号、operation/key、正文/sha256/字节数、dispatch 时使用的 session id、状态和恢复到期时间。Hermes run id 保存在关联的 `runs` 记录中，不在 queue item 重复存储。

MVP 不建立独立 `operations` 表；`operation_id` 和 idempotency key 都是 queue item 的不可变字段。

- `queued` 可编辑/取消；正文无自动 TTL。
- 从 `dispatching` 起不可编辑。
- `completed` 对账后状态为 `done` 且正文必须为 NULL。
- 非成功/歧义结果为 `paused` 或 `review_required`，正文最多保留到 `recovery_expires_at`。
- 到期清正文、记录 `payload_expired_at`，控制记录仍可保留用于解释状态。

### 4.4 `runs`

保存 local run id、Hermes run id、本地协调状态、上游原生 status、`partial`、最后事件序号/名称、事件是否截断和安全错误码。不得保存完整输出、delta、工具参数或回答摘要。

`local_state` 与 `upstream_status` 必须分列：`reconciling` 不是 Hermes status，`partial` 也不是 status。

### 4.5 `coordinator_leases`

保存全局和会话 scope 的短租约、owner、随机 fencing token、heartbeat 和 expiry。取得租约不能替代数据库 partial unique index；二者共同避免进程重入和重复 dispatch。

### 4.6 `ui_preferences` 与 migration

只保存无敏感信息的界面偏好和 schema migration 版本。Hermes/API/provider key 只能来自服务端环境变量，不能写 SQLite。

## 5. 核心数据流

### 5.1 读取列表和历史

```text
Browser GET /api/v1/conversations
  -> Hermes GET /api/sessions?source=api_server
  -> 过滤/验证 root list 结果
  -> SQLite 惰性建立 conversation 引用并左联 tags/order/queue state
  -> 安全投影给 Browser

Browser GET /api/v1/conversations/{local_id}/messages
  -> 读取当前 hermes_session_id
  -> Hermes GET /api/sessions/{id}/messages
  -> 若响应 effective id 变化，事务更新引用
  -> 返回当前 segment 投影与固定 scope 提示
```

上游失败必须返回错误，不能用本地引用伪装成成功会话列表或消息历史。

### 5.2 保存草稿与发送

```text
PUT /api/v1/conversations/{conversation_id}/draft(content, expected_revision)
  -> SQLite CAS 保存；不接触 Hermes

POST /api/v1/conversations/{conversation_id}/messages(client_request_id, expected_draft_revision)
  -> 要求 Hermes healthy
  -> SQLite transaction:
       校验 draft revision
       从已保存 draft 读取正文；请求本身不携带正文
       创建 queue_item + operation/key + fifo_seq
       清除 draft
  -> coordinator 尝试取得 global + conversation lease
  -> 若可用则 dispatch；否则保持 queued
```

离线发送在创建 queue item 前失败，草稿保持原样。

### 5.3 提交 run

```text
queue item queued
  -> transaction: dispatching + session snapshot + attempt/deadline
  -> POST Hermes /v1/runs，同 key/body/session
  -> 202: transaction 保存 run_id，状态 accepted；正文继续保留
  -> 唯一 upstream SSE consumer + status polling/recovery
  -> terminal: GET run status + GET messages
```

- 若无 `run_id` 且 admission 结果不确定，只在 deadline 前以同一三元组恢复。
- 有 `run_id` 后只读 status/messages，永不再次 POST 输入。
- `completed` 且 messages 对账成功：更新 effective session id，清正文，标记 done，释放 slot，必要时 dispatch 下一项。
- 其他终态：设置 7 天恢复到期、暂停队列、释放 slot，不 dispatch 下一项。

### 5.4 事件 fan-out

上游事件只进入每 run 最多 512 条或 1 MiB 的进程内 ring buffer。浏览器 SSE 使用本地递增 seq；本地 seq 不是 Hermes replay cursor。进程重启或环形缓冲缺口用 `stream.gap`/snapshot 标记，不落 SQLite 补齐。

### 5.5 删除

1. 拒绝存在本地 active run 的 conversation；用户先 stop 并等待收尾。
2. 后端读取 Hermes detail 和 `/health/detailed`；全局 `active_agents > 0` 时保守拒绝。
3. 调用 Hermes DELETE；超时/5xx/未确认 404 保留 `delete_state`。
4. 明确成功或独立 GET 确认不存在后，事务删除本地 conversation（级联草稿、队列、run）。

该门禁无法消除其他客户端在检查与 DELETE 之间启动 run 的竞态，UI 必须把它描述为当前 Hermes 能力下的保守保护，而非原子保证。

## 6. 信任边界和禁止事项

- 禁止浏览器获得 Hermes key、provider key、环境变量或上游 base URL。
- 禁止直接访问 Hermes `state.db` 或从参考源码 import 运行逻辑。
- 禁止 messages/tool_events/transcript/FTS 镜像表和用 IndexedDB 长期保存历史。
- 禁止发送 `X-Hermes-Session-Key`。
- 禁止把 202、SSE 终态或正文相同当成输入已持久化证明。
- 禁止已有 `run_id` 后重新 POST 原输入。
- 禁止多条后端连接同时消费同一个 Hermes run events endpoint。
- 禁止解析 Markdown/preview 推断 checklist。
- 禁止 archive/restore 和 OpenAI-compatible fallback。
- 禁止在 raw HTML、tool arguments、preview 或错误文本上绕过 sanitizer/脱敏。

## 7. 内部模块边界

依赖方向固定为：

```text
routes -> application services/coordinator -> repositories + hermes adapter
client -> typed browser API client + view models
shared -> schemas/enums only，不依赖 server/client
```

route 不直接写 SQL；repository 不发 HTTP；Hermes adapter 不操作 UI/SQLite；React 组件不判断上游协议字符串。详细目录和类型定义见 `11-Gemini编码交接基线.md`。
