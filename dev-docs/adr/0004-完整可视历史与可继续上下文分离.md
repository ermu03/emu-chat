# ADR-0004：完整可视历史与可继续上下文分离

- 状态：已接受
- 性质：MVP 历史边界
- 日期：2026-09-19

## 背景

Hermes 会因压缩轮换可继续上下文。API Server 的 `/api/sessions/{id}/messages` 会解析到当前 resumable tip，但不保证返回 compression lineage 中所有旧 segment。compression、branch 和 delegate 的父子关系也不能由客户端仅凭 `parent_session_id` 安全区分。

## 决策

1. MVP 的执行与阅读都使用 Hermes 返回的 effective/resumable session id。
2. UI 只展示该 endpoint 返回的当前 segment，并提示更早压缩段未展开。
3. emu-chat 不遍历或合并 parent/child sessions，不保存副本来补历史。
4. 完整逻辑时间线是未来能力；若加入，必须由 Hermes 提供正式、只读、分页且能区分 lineage 类型的投影。

## 后果

首版不能保证像传统聊天应用一样看到压缩前全部消息，但不会错误合并 branch/delegate，也不会破坏 Hermes 的唯一历史边界。
