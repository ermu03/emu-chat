# 会话生命周期与删除策略

状态：MVP 已批准实现基线
更新时间：2026-09-19

## 1. 术语

- **Hermes session segment**：一个具体 `session_id`，是 Hermes API 的读写地址。
- **effective/resumable segment**：Hermes 当前解析出的、可继续运行的 tip。
- **compression child**：因上下文压缩产生的 continuation。
- **branch child**：用户 fork 创建的替代会话。
- **delegate child**：Hermes 工具/子 Agent 创建的子会话。
- **emu-chat conversation**：指向当前 effective session 的本地稳定引用，不是 transcript。

emu-chat 不根据 parent、title 或时间自行推断关系。当前 tip 和删除行为以 Hermes API 为准。

## 2. MVP 生命周期动作

| 动作 | Hermes 调用 | emu-chat 结果 | 删除历史 |
| --- | --- | --- | --- |
| 新建 | `POST /api/sessions` | 新 conversation | 否 |
| 继续 | `POST /v1/runs` + 当前 session id | 终态后更新 effective id | 否 |
| 重置 | 创建全新 session | 新 conversation；旧会话保留 | 否 |
| 分支 | `POST /api/sessions/{id}/fork` | 新 child conversation | 否；Hermes 内部复制上下文 |
| 重命名 | `PATCH title` | 重新读取 Hermes detail | 否 |
| 置顶/取消置顶 | `PATCH pinned` | 重新读取 Hermes detail | 否 |
| 删除 | `DELETE /api/sessions/{id}` | 确认后清理本地引用 | 是，按真实 segment 语义 |

MVP 不提供 archive、unarchive、隐藏、恢复或“删除整个谱系”。这些动作不得出现在菜单、内部 Browser API 或快捷命令中。

## 3. 新建与重置

### 3.1 新建

成功顺序：

1. 调用 Hermes create；
2. 校验返回 session id；
3. 本地事务建立 conversation；
4. 返回浏览器并选中新会话。

若第 1 步成功而本地写入失败，响应为本地错误并在下一次列表读取时通过 Hermes 权威列表惰性发现该 session；禁止为了“补偿”再创建第二个空 session。

### 3.2 重置

重置语义是“以新空 session 开始”，不是清空当前 session，也不是删除。

- 当前 conversation 有 active run 时，重置 API 返回 `LOCAL_CONFLICT`；用户先 stop 并等待终态/人工复核。
- 成功后创建新的 conversation，旧 conversation、历史和队列状态原样保留。
- 不复制旧草稿、queue item、tags 或 custom order；前端可以切换到新 conversation。

## 4. 继续与 compression 轮换

每个 run 只携带当前 `conversation.hermes_session_id` 和新输入。完成或其他终态后，后端读取：

```http
GET /api/sessions/{known-id}/messages
```

若响应顶层 `session_id` 变化：

1. 校验新 id 非空、消息响应合法；
2. 在同一事务更新 conversation 的 `hermes_session_id` 和 `last_seen_upstream_at`；
3. 后续 run 只使用新 id；
4. 不自行沿 parent 拼接旧消息。

用于继续的 tip 与完整可视历史是两种资源。MVP 只承诺 tip 的当前 segment，并显示范围提示。

## 5. 分支

分支 UI 固定文案：“从当前 Hermes 会话创建独立分支。新分支有独立的后续消息和队列；父会话不会被删除。”

成功后：

- 只使用 Hermes 返回的 child id/title/parent 信息；
- 建立新的空本地 queue/draft；
- 不复制 messages、run、事件或本地 tags；
- 父 conversation 仍可读写。

fork 失败不修改父 conversation，也不创建本地占位 child。

## 6. Title、pinned、hidden 与 archived

- title 和 pinned 由 Hermes 权威；Browser API 成功 PATCH 后必须重读 detail。
- Hermes 的 pinned 更新可能按 compression lineage 生效且清除 hidden。置顶确认/帮助文本必须说明这是 Hermes 元数据的实际影响，而非单一页面本地星标。
- hidden 若出现在 Hermes 响应中只作为只读标志显示；MVP 没有 hide/unhide 动作。
- archived sessions 默认不会出现在当前 list，且无法由现有 route 完整重新发现；MVP 完全移除 archive/restore UI 和 API。
- emu-chat 本地只有 tags/custom order，不得伪装成 Hermes title/pinned/hidden/archive。

## 7. 删除范围

Hermes 当前 DELETE 的真实语义固定为：

1. 删除指定 session segment；
2. 删除 Hermes 定义的 delegate children；
3. branch/compression children 不级联，可能成为 orphan；
4. 不删除长期记忆、附件、artifact、工具生成文件或日志；
5. 不提供原子 `lineage/subtree` scope。

因此按钮固定命名为“删除当前 Hermes 会话段”，不能写成“删除全部聊天”或“删除整棵会话树”。emu-chat 不通过客户端遍历 children 后逐个 DELETE 模拟原子树删除。

## 8. 删除确认内容

确认弹窗必须显示：

- 当前 Hermes session id（可折叠/复制）；
- title（只作辅助，不作为目标标识）；
- “目标段及 delegate children 将被删除”；
- “branch/compression children 不保证删除，可能成为 orphan”；
- “长期记忆、附件、artifact 和工具文件不会随之删除”；
- 不可逆提示；
- 用户必须勾选确认后才能提交。

Browser API 请求还必须带 `expected_hermes_session_id`；若本地引用已轮换则返回 `LOCAL_CONFLICT`，要求用户刷新确认范围。

## 9. 删除门禁与执行

1. 读取本地 conversation；验证 expected id。
2. 若该 conversation 有 `dispatching|accepted|reconciling` item，返回 `RUN_ACTIVE`，不自动组合 stop+delete。
3. GET Hermes detail；若此时已 404，记录只读证据并进入本地收尾。
4. GET `/health/detailed`。若无法读取或 `active_agents > 0`，返回 `HERMES_BUSY_GLOBAL`；MVP 无 force delete。
5. 调用 Hermes DELETE。
6. 2xx：本地事务先显式删除该 conversation 的 lease，再删除 conversation；draft/queue/run 依赖外键级联。global lease 不在此处删除。
7. DELETE 404：再次 GET detail；只有 GET 也明确 404 才按已不存在收尾。
8. 超时、断线、5xx 或无法对账：保留 conversation，设置 `delete_state=pending|failed` 和安全错误码。
9. 最后重新读取列表；如果仍出现该 id，显示冲突而非隐藏。

全局 active count 不是 session-scoped 原子锁，检查与 DELETE 之间仍可能竞态。当前方案是保守门禁，不是完整安全保证。

## 10. 删除状态

| 情况 | 本地处理 | UI |
| --- | --- | --- |
| 本地 active run | 不发 DELETE | 先停止并等待收尾 |
| Hermes 全局 active agent 非零/未知 | 不发 DELETE | 稍后重试；无 force |
| 明确 2xx | 事务清本地 | 删除成功 |
| DELETE 404 + detail 404 | 事务清本地 | 已不存在，完成本地清理 |
| DELETE 404 但 detail 可读/读取失败 | 保留 | 删除结果未确认 |
| 超时/连接断开 | `pending` | 重新核对，不重复假装成功 |
| 明确 4xx/5xx | `failed` | 显示安全错误，可重新发起完整流程 |
| 上游成功后本地崩溃 | 下次 detail 404 后收尾 | 恢复本地清理 |

本地隐藏、按钮禁用、HTTP 请求发出都不是删除成功证据。

## 11. 非联动资源

MVP 不提供 memory/file/artifact 清理。删除弹窗和完成提示均说明这些资源未处理。未来若增加，必须是独立、有资源预览、逐类结果和二次确认的 API，不能扩展现有 DELETE 的含义。
