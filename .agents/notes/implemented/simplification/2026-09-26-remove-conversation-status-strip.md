# Agent Note: 移除会话区的 Hermes 状态条

Status: implemented

## Problem

原会话区在有会话和空工作区两处挂载 Hermes 状态条。连接健康但带有 `lan_http_warning` 时，仍会出现“在线 / 重新检测”横栏，与侧栏底部已有的连接状态重复。该状态条又是页面唯一的手动重检入口；直接删除会使首次探测异常后的发送功能只能靠整页刷新恢复。

## Decision

从 [AppShell](../../../../src/client/app.tsx) 的两个分支移除状态条，删除未再使用的组件和 `.status-strip` 专用样式。连接状态仍由 AppShell 初始化读取并用于发送就绪判断；侧栏只接收完整的状态响应、加载进度、请求错误和重检回调，不自行探测或维护第二份状态。异常、配置错误与状态读取失败在[侧栏连接区域](../../../../src/client/features/conversations/conversation-list.tsx)显示原因；能力不兼容时显示缺失数量。重检沿用原状态 API，检测期间禁用按钮，成功后更新原有状态并恢复发送。

折叠侧栏保留带可访问名称的重检按钮，移动端会话列表抽屉中也可使用。局域网 HTTP 标记及服务端状态字段保留，但不再触发会话区横栏。SSE 重连、会话加载和发送失败仍使用各自的提示链路；状态请求失败由侧栏呈现，不再产生重复的主区域错误提示。

这延续[界面入口简化决定](../feature/2026-09-24-remove-settings-fix-sidebar-and-add-rename.md)及[清理未使用路径决定](./2026-09-25-remove-unused-paths-and-build-artifacts.md)。

## Alternatives considered

- **只让健康状态忽略局域网 HTTP 标记，异常时保留中间状态条**：改动较小，也能消除健康时的重复“在线”行；异常时仍占用会话区，不符合移除整条横栏的需求。
- **删除状态条及重检入口**：界面和代码最少，整页刷新也能重新探测；但上游恢复后仍需中断当前页面，且发送按钮不会自动解禁。侧栏已有状态区域，容纳重检操作更合适。

## Consequences

会话内容区不再因连接状态或局域网 HTTP 标记增加一条横栏；初次状态请求失败后可在侧栏重试，成功恢复时草稿与发送就绪状态继续保留。折叠和移动布局中的重检入口较桌面展开侧栏更难发现，因此保留明确的按钮名称、加载反馈和底部固定位置。连接健康时侧栏仍只显示紧凑状态，不增加定时健康轮询。

## Verification

[跨模块组件测试](../../../../tests/components/app-shell-flow.test.tsx)覆盖首次状态请求失败、折叠侧栏重检失败、移动抽屉再次重检成功，并确认草稿未丢失及发送重新可用。相关组件测试共 11 个用例通过；`npm run typecheck`、`npm run lint`、`npm run format:check` 与 `npm run build` 通过。本地浏览器在桌面、折叠侧栏、移动宽度及空工作区下检查了布局；模拟配置错误及局域网 HTTP 标记时会话区没有横栏，重检健康后发送恢复。验证使用 Node.js 26，项目要求的 Node.js 22 环境尚未验证。
