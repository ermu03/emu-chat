# Agent Note: 上游 SSE 断线恢复与连接释放

Status: implemented

## Problem

原协调器在上游断线后结束 `consume`，后续只轮询状态；启动恢复已接纳 Run 时也不恢复事件消费。仍在运行的任务因此失去后续文字和工具反馈。`HermesClient.stream` 的收尾只清除握手计时器，生成器提前结束后请求未中止、reader 没有取消且响应仍被锁定。

真实上游恢复能力必须先核实。本地 `local_seq` 只代表转发顺序，不能充当上游恢复游标；相同文字和时间戳也不能证明两次增量是重复事件。

## Decision

1. 核对本机 Hermes 提交 `6005aa1` 并直接执行其 handler 的[隔离验证](../../../research/2026-10-05-hermes-run-sse-contract.py)：Run SSE 没有事件 ID、游标或重放，读取一次性内存队列；连接正常结束或写入失败后删除队列，保留独立状态，原 Run 的后续订阅返回 404。EOF 本身不代表 Run 终态。详细来源及边界记录在[Hermes 集成说明](../../../../docs/05-hermes-integration.md#run-sse-的续订边界)。
2. [协调器](../../../../src/server/coordinator/admission-coordinator.ts)按 Run 持有单一消费者、捕获的租约对、取消信号、连接尝试数和退避计时器。初次接纳立即订阅；启动恢复和轮询在有效租约下，为仍处于 accepted 的原上游 Run 补建消费，不调用 `startRun`。消费独立于派发 tick 和提交单飞，不让长连接阻塞调度。
3. 非终态 EOF 和临时错误记录 `events_truncated` 并发布 `upstream_disconnected` 缺口。当前租约下最多连接 4 次，重试等待 1、2、4 秒。404、鉴权、协议等不可重试错误停止续订；尝试用尽也保持停止状态，重复唤醒不能绕开限制，REST 继续确认终态。只消费上游队列仍可用时未取出的事件，不按内容猜测去重，不伪造游标；浏览器有界缓冲回放仍由本地序号去重。
4. [Adapter](../../../../src/server/hermes/adapter.ts)透传取消信号，[Client](../../../../src/server/hermes/client.ts)在等待读取时响应取消，正常结束、提前退出和解析错误都中止请求、取消 reader 并释放锁。租约释放、REST 确认终态和服务停止取消消费与重试；服务关闭等待消费者收尾后再关闭数据库。旧消费者收尾前保留登记，每次事件和退避回调复核消费者身份、捕获的租约对和有效令牌，旧回调不能写入或取消新消费者。
5. 沿用[集中生命周期决定](../architecture/2026-09-26-centralize-run-lifecycle-and-recovery.md)的事务、状态对账单飞和租约保护，以及[实时到历史交接](../feature/2026-09-24-progressive-tool-events-and-stable-run-handoff.md)的展示保留。用户停止请求不是上游终态，继续消费与轮询；`user_stopped` 暂停不被终态竞争或历史重试清除。

## Alternatives considered

- **继续只轮询状态**：可靠地推进终态，也不需要处理上游回放；但在队列仍可用的临时连接失败和启动恢复中会失去所有后续反馈，因此保留为有限续订之后的兜底。
- **无限重开 SSE 或按内容去重**：可更快恢复新事件，且实现入口较少；真实上游删除队列后无限重试没有收益，相同文字增量可能都是合法内容，也没有可用于去重的事件身份，因此不采用。
- **同时扩展上游游标协议或持久化本地事件副本**：稳定身份和可重放日志能提供完整恢复；但需要独立的跨仓库协议与保留策略，本地保存已收到事件也不能取回上游已经丢掉的事件。本次只落实现有契约允许的恢复和连接收尾。

## Consequences

原 Run 在允许续订时可恢复新文字和工具反馈，停止、终态、租约换主和服务关闭能够释放连接及计时器；断线缺口跨重连保持可见。调度继续轮询权威状态，不创建第二次执行，也不提前清空实时内容。

当前部署的 Hermes 断线后通常删除事件队列，所以完整过程恢复仍不可能；正常服务关闭也可能让上游删除队列，下一进程恢复到 404 后只能轮询终态与核对历史。恢复不承诺取回断线期间的事件。连接尝试限制随消费者所属租约和进程生存期保留，没有新增持久事件副本。上游将来引入重放时，必须先明确稳定身份、游标范围和重启语义，再修改续订协议。

## Verification

- [客户端资源测试](../../../../tests/unit/hermes-client.test.ts)覆盖提前结束、等待读取期间取消、Adapter 协议拒绝和空闲超时。
- [生命周期并发测试](../../../../tests/unit/run-lifecycle.test.ts)覆盖单消费者续订、合法相同增量、有限重试、404 回退、退避取消、租约换主隔离，以及 REST 确认终态先释放连接再等待历史。
- [主干集成测试](../../../../tests/integration/phase4-queue-runs.test.ts)覆盖真实 HTTP 503 后续订、新文字和工具转发、活跃 Run 重启恢复及不重复接纳。模拟上游只消费未取出的事件；该用例特意保留队列以验证可恢复路径，真实 Hermes 删除队列的边界另由源码隔离验证与 404 生命周期测试确认。
- 现有跨模块展示、停止与历史延迟测试继续验证内容和展开状态保留，终态交接及用户暂停语义。
- 实施时全量 19 个测试文件、115 个用例通过；类型检查、lint、格式检查和前后端构建通过。构建仍有既存的客户端大包提示。本机 Hermes 相关源码相对上述提交无修改；隔离验证通过，未调用真实 Agent。
