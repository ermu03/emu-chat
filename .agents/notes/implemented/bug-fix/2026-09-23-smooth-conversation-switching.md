# Agent Note: 减少会话切换空白与消息重绘

Status: implemented

## Problem

冷缓存切换时，[AppShell](../../../../src/client/app.tsx) 会先清空当前会话状态；[MessageView](../../../../src/client/features/messages/message-view.tsx) 因此短暂显示空加载区。与此同时，流式 token 更新会让 AppShell 重渲染，而 MessageView 每次都会重新分组消息并重新渲染历史 Markdown。长对话由此出现空白切换和不必要的重绘。

## Decision

1. 为消息列表记录所属会话 ID。缓存未命中的目标会话加载期间，通过 `currentViewSnapshotRef` 保留最后展示的会话视图，并继续用原会话标题标识当前内容；顶部提示正在加载的目标会话。消息请求独立完成后立即切换消息视图，不被详情、草稿或队列请求拖住；草稿、队列和运行控制只对已加载的目标会话开放。
2. 目标消息加载成功后切换到目标视图；加载失败时保留旧视图并显示重试入口。首次打开且没有旧视图时继续显示加载状态。缓存命中时立即恢复目标快照并后台刷新。
3. `MessageView` 仅在 `messages` 引用变化时重新分组；用户、系统、助手、工具行和 Markdown 内容使用 `React.memo`。纯流式内容更新会刷新活动回复，但稳定的历史消息行和 Markdown 不会重复渲染。
4. 按展示会话 ID 为 `MessageView` 建立组件边界，避免上一个会话的滚动跟随状态污染下一个会话。

## Alternatives considered

- **切换时清空并显示加载态**：实现直接，且不会暂时展示旧内容；但消息区会闪空，未命中缓存时更明显。
- **只显示骨架屏**：能说明目标正在加载，却会隐藏当前已可读的内容，不能保持切换期间的视图稳定。
- **直接引入虚拟列表**：可减少超长历史的 DOM 数量；滚动定位、动态高度和流式消息会增加复杂度。当前先消除每次 token 更新的重复分组与 Markdown 渲染，虚拟化留待实测需要时评估。

## Consequences

- **收益**：冷切换期间保留可辨识的旧视图，明确标出加载目标，并阻止会话级操作落到错误会话；失败后可以直接重试。流式更新不会重新解析稳定的历史 Markdown。
- **代价**：当前由 [useConversationView](../../../../src/client/state/use-conversation-view.ts) 追踪选中会话与消息列表所属会话，并保留展示快照。切换到另一个会话时 MessageView 会重新挂载并从底部开始；当前没有按会话保存滚动位置。消息列表本身变化时仍会重新分组，虚拟化是否必要还需通过真实长会话评估。

## Verification

实现后运行类型检查和 lint；未新增或运行测试。目标消息请求与其他会话数据请求分别处理，避免非消息请求延迟消息视图切换。
