# Agent Note: 识别完整 HTML 片段

Status: implemented

## Problem

[成果预览首版](../feature/2026-09-26-add-html-svg-artifact-preview.md)只允许完整 HTML 文档。Hermes 实际会在回复正文或 `html` 围栏中输出单个 `<div>…</div>` 卡片，用户看见原始标签或仅有“复制代码”，没有“打开预览”。即使要求模型补上代码围栏，片段仍不满足完整文档条件。

## Decision

已保存的助手正文里，`html` 围栏除了完整文档，也接受具有单个根元素、显式闭合标签的 HTML 片段。正文中由 Markdown 识别出的 HTML 块同样可提取一个完整根片段；若同一块的闭合标签后还有说明，只把片段作为成果，说明保留在消息中。提取后仍在原位置显示带“打开预览”的代码块。解析使用不创建浏览器元素的 parse5，并拒绝解析错误、缺失结束标签和超过 256 KiB 的内容；不完整片段继续按文本或普通代码显示。预览沿用现有 CSP 与 sandbox iframe，用户点击后才运行。

## Alternatives considered

- **继续要求完整 `<html>` 文档**：界限最清晰，但单个卡片和按钮是模型的自然输出，用户必须反复要求包装，代码围栏本身也无法解决。
- **在聊天正文中直接解析并注入 HTML**：可立即显示样式，却会绕过成果面板的隔离与主动预览边界。
- **容忍自动补全的未闭合片段**：能展示更多流式或截断内容，但预览结果可能与模型原意不同，难以区分完整成果和半成品。

## Consequences

用户截图中的单根 `<div>` 卡片无论位于正文还是 `html` 围栏，都会得到同一个预览入口。多根并列片段仍需包进一个容器或完整 HTML 文档；HTML 解析器的规范化结果不写回源码和下载文件。片段在 iframe 中作为文档正文运行，原有 HTML 网络隔离限制仍适用。

## Verification

- 提取测试覆盖围栏片段、正文片段与后续说明分离、缺失结束标签；交互测试覆盖两种片段都能打开 HTML 预览，以及用户消息无入口。
- `npm run typecheck`、相关 Vitest、`npm run lint`、`npm run format:check`、`npm run build` 通过。
