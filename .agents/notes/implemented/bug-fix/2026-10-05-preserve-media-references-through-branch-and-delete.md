# Agent Note: 分支与删除过程中的图片引用保护

Status: implemented

## Problem

2026-10-05 的内存 SQLite 与模拟插件复现确认了两个图片关联缺口。

其一，[MediaBranchService](../../../../src/server/media/branch.ts) 的 A→B 分支产生 1 条输入图片映射，但 B→C 分支产生 0 条映射并被标记为完成。复制到 B 的用户消息仍带 A 的原始清单，当时分支只接受 scope 属于直接来源 B 的清单，没有读取 B 已验证的 `media_branch_messages`。工具图片还按原始资源的来源 session 过滤，需要一并覆盖继承的输出图片。

其二，[MediaSyncWorker](../../../../src/server/media/sync.ts) 在会话 `delete_state` 不为 `none` 时，把尚未执行的普通同步任务直接标成 `done`。隔离复现中，删除因 Hermes 忙碌而撤销、会话恢复可用，但引用写入调用次数为 0，任务已完成且无法重试。当时分支 `sync` 遇到目标临时删除状态也会提前返回，其调用方随后标记完成。

这些问题共同违反[图片工作流决定](../../implemented/feature/2026-09-28-add-image-workflows.md)和[图片规格](../../../specs/2026-09-28-image-workflows.md)中的约束：关联完成前保护来源，临时故障后继续同步，确认删除后才释放引用。文本保留期限另由[正文清理决定](../../implemented/bug-fix/2026-10-05-clear-frozen-queue-payloads.md)处理。

## Decision

分支仍以 Hermes 权威复制顺序和完整消息身份配对，只处理冻结的复制前缀。继承图片读取直接来源 scope、原消息 ID 对应的已验证 `media_branch_messages`；输入图再核对清单 operation 与资源顺序，工具图核对工具类型及调用身份。从直接来源的有效权限授予目标，验证响应中的目标 scope 和资源 ID，保留原 operation 与插件不可变来源元数据。来源自身的新消息继续按提交绑定或工具来源验证，不能根据其他 scope 的机器清单直接扩大权限。

直接来源分支尚未完成时，后续分支延期，避免在 B 尚未建立映射时提前完成 B→C。逐项授权和分支引用均成功后，在同一即时事务内复核目标并写入映射与 `done`；关联待处理期间继续保护来源。相同目标的直接调用与 worker 共用进行中的 Promise；停止服务等待分支调用以及两侧历史读取全部收尾。部分远端成功后仍按原身份重试。

普通 outbox 和分支任务区分可用、暂态删除与本地已确认移除。`pending`/`failed` 保持待处理，普通任务延期 2 秒且不增加失败次数，分支任务延期 10 秒；到期筛选允许其他 scope 前进。每次网络调用前后及最终本地提交前复核目标。删除撤销后原任务恢复；确认移除后结束失去用途的普通任务，分支记录由外键级联删除。独立的 `scope_delete` outbox 继续原有持久重试，不受本地记录移除影响；迟到写入由插件删除墓碑阻断。

新增增量迁移 `0005_media_branch_retry.sql`，保留现有草稿、队列和映射，补下次尝试时间。旧版本误报完成的继承分支及其后续分支，在仍存在直接来源且能追溯到已验证映射时重新进入待处理；后续任务等待直接来源修复完成。直接来源已删除的旧缺图无法据此安全恢复，不凭更早清单猜测权限。

## Alternatives considered

- **对分支复制来源 scope 的全部资源授权**：实现简单，能避免清单仍指向更早 scope 时漏图。但会授予实际没有复制的消息或来源未来消息的图片，破坏分支权限边界。
- **删除开始时就结束普通同步任务**：可减少对即将删除 scope 的无效请求。但删除可能因健康检查、忙碌或网络失败而撤销，必须保留暂态期间的恢复能力。
- **删除撤销后重新全量扫描并重建引用**：可补偿部分丢失关联。但来源和关联身份可能已变化，且需要额外扫描和未知引用的处理；保留原持久任务更容易维持幂等与来源证明。

## Consequences

连续分支保留实际复制消息的输入图与工具输出图，映射使用各目标的新消息 ID；删除祖先会话不影响后代的独立权限。引用失败、插件离线、服务重启及删除撤销可沿持久任务继续，完成前来源保护不会提前解除。文档见[服务端说明](../../../../docs/04-server-internals.md)和[图片维护说明](../../../../docs/11-image-workflows.md)。

两库间仍无法原子提交，依赖幂等授权、固定引用 ID、来源保护和删除墓碑；短暂延期增加恢复等待。升级可能重新核对旧继承分支，核对完成前暂时阻止删除来源。若旧直接来源已被删除，或原历史已不可读，不能无依据补建授权；这种情况需要保留数据并核对插件和历史备份。本修复不改插件协议，不重新调用模型。
