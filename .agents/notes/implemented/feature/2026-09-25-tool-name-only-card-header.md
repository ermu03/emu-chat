# Agent Note: 工具卡片标题只显示工具名

Status: implemented

## Problem

原方案在折叠标题显示工具名和调用摘要，便于执行时辨认命令。实际使用主要在助手完成回复后查看工具结果；卡片展开区已经包含完整输入和输出，一行标题不需要重复参数。原决定见[归档笔记](../../archived/feature/2026-09-25-show-tool-invocations-in-cards.md)。

## Decision

工具卡片折叠标题左侧只显示工具名，右侧保留执行状态。展开后继续显示完整的脱敏命令或参数，以及结果。实时 `tool.started.preview` 不进入卡片展示状态；`tool.completed.preview` 仍作为历史结果到达前的临时输出。历史消息 API 的每个展示调用只保留 `id`、`name` 和可选的 `display_args`，不生成标题摘要。Hermes 的事件协议保持不变。

服务端仍在浏览器收到 SSE 和历史消息前，对约定名称的凭据遮盖；工具结果按 `tool_call_id` 与历史调用精确配对，实时同名并发调用不猜测归属。这些约束承接原方案。

## Alternatives considered

- 保留原来的单行调用摘要，运行时一眼能看到命令；实际查看集中在回复完成后，摘要与展开区输入重复，长参数还挤占标题空间。
- 完全不展示工具输入，可以进一步缩减历史接口；完成回复后仍需要核对具体命令和参数，因此保留展开区。

## Consequences

标题更短，工具类型和状态容易扫读；查看具体调用需展开卡片。浏览器消息接口不再承载仅供标题使用的摘要字段，完整输入仍经过服务端遮盖。同名并发工具在实时阶段仍需等权威历史才能准确配对。

## Verification

类型检查及消息流转、历史配对和展示遮盖的相关测试确认摘要字段已移除，展开区输入输出仍可读取。
