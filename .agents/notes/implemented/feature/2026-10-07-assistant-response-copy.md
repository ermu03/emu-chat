# Agent Note: 助手回复与代码复制操作

Status: implemented

## Problem

用户采纳[对话展示调研](../../../research/2026-10-07-chatgpt-conversation-ui.md)中的回复操作方向。现有助手回合缺少整段复制；普通代码有复制，可预览成果则用预览按钮替代复制。复制失败目前没有明确反馈。

## Decision

助手回合底部提供小型复制入口，复制按显示顺序组成的助手正文，保留 Markdown 和代码围栏；不包含思考、工具日志、状态提示或图片机器清单。正常复制在回复结束后开放，停止后的已有文字也可复制。触屏入口直接可用，桌面悬停/键盘聚焦可以增强显示；提供成功与失败反馈。

代码块复制只取原代码，同时提供复制与预览。处理 Clipboard API 不可用的手动选择备用入口，延续成果预览的来源验证与执行边界。与[工具展示](../../proposed/feature/2026-10-07-lightweight-tool-display.md)分离正文及日志复制。

## Alternatives considered

- 直接复制整行 DOM 文本：实现简便，但会混入工具、按钮和状态文案，无法保持代码格式。
- 所有回复只提供原始 Markdown 下载：便于保留格式，但增加日常复制的操作成本。

## Consequences

回合按正文块的发生顺序用空行连接 Markdown 源文；思考、工具与界面状态不会进入复制内容。结束或停止后的已有文字可复制，进行中的正文不开放整段复制。代码复制与预览共存，预览来源和 sandbox 约束保留。

复制成功反馈持续两秒；失败及 Clipboard API 缺失时提供可选中的只读原文，供 HTTP 和受限浏览器手动复制。反馈按当前内容及会话身份隔离。手动复制区会临时增加消息高度，关闭后恢复。

## Verification

- 类型检查、lint 及已有 18 个 AppShell 异步交互测试通过；两个新增用例覆盖复制来源一致性、会话切换和迟到成功/失败回调。
- Chromium 390px 触屏样例确认回合/代码实际剪贴板内容、复制与预览并存、手动选择备用入口及无整页横向溢出。
