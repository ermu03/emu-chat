# Agent Note: 工具调用展示轻量化

Status: implemented

## Problem

用户在 2026-10-07 采纳[对话展示调研](../../../research/2026-10-07-chatgpt-conversation-ui.md)中的方向，并确认理解工具展示的具体方案。现有工具调用默认虽折叠，但每次都有完整边框、背景和状态胶囊，连续调用占用较多阅读空间。

## Decision

首期采用紧凑、可展开的工具状态行，保留真实工具名，不恢复参数摘要。运行时显示小型活动指示，成功状态弱化，失败醒目并默认展开。展开区保留脱敏输入、输出；长结果先显示有限内容，再主动查看完整内容。保留用户展开状态和现有实时到历史的稳定交接。

首期不合并多次调用，不移动正文、思考、工具或图片的相对顺序。工具图片结果独立于详情折叠，采用[生成图片方案](../../proposed/feature/2026-10-07-generated-image-result-cards.md)。承接[工具名决定](2026-09-25-tool-name-only-card-header.md)及[交接决定](2026-09-24-progressive-tool-events-and-stable-run-handoff.md)。

## Alternatives considered

- 保留完整卡片、仅减少内边距：改动最少，但连续重复边框和成功胶囊仍突出。
- 首期直接合并全部工具调用：更省空间，但可能重排穿插正文并破坏展开状态，先保留逐项展示。

## Consequences

工具折叠行去除常驻边框和成功胶囊，桌面高度 32px、触屏最小 40px；工具名、运行/完成/失败/待核对状态保留，错误默认展开。长输出默认最多 24 行/3000 字符，再由用户展开完整内容，完整内容在局部区域滚动。

详情与完整输出的选择均由助手回合按工具序号持有，延续现有实时到历史交接规则。同名并发继续等权威结果，不合并调用、不重排正文及工具。生成图片仍独立于详情折叠，图片布局在独立提案实施。

## Verification

- Chromium 样例检查 32px 折叠行、长输出展开/收起、深色触屏布局及视口改变后旧消息阅读位置。
