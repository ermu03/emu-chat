# Agent Note: 生成图片结果卡片与阶段反馈

Status: implemented

## Problem

用户采纳[对话展示调研](../../../research/2026-10-07-chatgpt-conversation-ui.md)中的图片展示方向。现有生成结果与上传附件共用 126px 缩略图；资源出现前没有图片占位，保存状态与模型生成阶段的反馈不完整。下载、复用需先打开查看器。

## Decision

为生成结果设置独立大图布局，桌面单图最大宽度从约 400–480px 起步，窄屏自适应，保留原图比例，多图使用网格；上传附件保留紧凑展示。结果旁提供下载与“用于下一条消息”，点击图片沿用大图查看器，技术详情单独折叠。

已明确识别生图工具开始时提供保守尺寸的占位，区分正在生成、正在保存、已就绪、生成失败、保存失败、暂不可用及待核对。使用不定进度反馈，不编造百分比或预览。权威图片就绪后尽量原位替换，延续[图片补读修正](../bug-fix/2026-09-30-complete-generated-image-refresh-and-recovery.md)。同名并发仍待权威历史配对，保存重试不重新调用付费模型。

## Alternatives considered

- 把所有附件缩略图放大：最少组件改动，但输入区和队列附件也会显著挤占空间。
- 生图结果只放进工具详情：结构简单，但用户必须展开技术记录才能查看主要结果。

## Consequences

生成结果采用独立布局：单图卡片最大 480px，多图两列、最大 720px，窄屏随正文宽度缩放；保留原比例并限制高度，上传附件继续保持紧凑。结果旁直接下载与追加草稿，点击图片沿用查看器。未知透明通道时使用中性底色，不一律铺棋盘。

只有已识别的 image_generate 调用在资源出现前显示占位；实时生成、工具完成后保存、失败及待核对分别提示，未确定的同名并发不猜测归属。保存等待及采集重试超过 90 秒提示尚未完成，并提供刷新历史入口；状态仍以服务器附件为准，已有有界补读和采集重试不变。历史刷新回调保持稳定，避免重建历史代码入口及丢失焦点。

旧会话的采集重试失败回调被隔离，已就绪的权威附件优先于旧重试覆盖。复用不自动发送，重试保存不再执行模型。未知尺寸仍可能在权威结果到达时改变占位比例。

## Verification

- 全量 20 个测试文件、124 个用例通过；类型、lint、格式与构建检查通过。核心 AppShell 与操作交互用例检查生成→保存→历史图片就绪以及跨会话迟到重试失败隔离。
- Chromium 样例检查单图 480px 卡片、按原比例显示、查看器、复用到草稿、手机多图网格、深色主题及生成/保存/待核对/失败阶段，无模型调用。
