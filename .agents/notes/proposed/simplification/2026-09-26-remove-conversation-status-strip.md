# Agent Note: 移除会话区的 Hermes 状态条

Status: proposed

## Problem

用户希望移除中间会话区的“Hermes 在线 / 重新检测”一行，减少与聊天内容无关的常驻界面元素。2026-09-26 基于提交 `ed84bde` 调研确认，该行由 [StatusBar](../../../../src/client/features/status/status-bar.tsx) 渲染，[AppShell](../../../../src/client/app.tsx) 在选中会话和未选中会话两个分支中都挂载了它。

当前组件在连接健康且没有 `lan_http_warning` 时已经隐藏；健康状态下出现这行，需要 `lan_http_warning = true`。[状态路由](../../../../src/server/http/routes/status.ts)根据请求主机名和协议生成该标记，[StatusService](../../../../src/server/services/status-service.ts)将其附加到响应。因此，在被判定为局域网 HTTP 的访问中，即使 Hermes 正常，也会展示带警告图标的“在线”文字和重检按钮。这里是代码条件核对，未连接用户页面验证实际请求标记。

[会话侧栏](../../../../src/client/features/conversations/conversation-list.tsx)底部已有连接状态点和文字，中间健康提示与它重复。StatusBar 本身不负责探测或 SSE，可以从中间布局移除；但它是当前页面唯一调用 `loadStatus(true)` 的入口。AppShell 只在初始化时主动加载健康状态，且 `sendDisabled` 依赖 `status.status === 'healthy'`。直接删掉全部重检入口后，初次探测异常的页面需要整页刷新才能重新取得健康状态并恢复发送。

## Proposal

移除中间会话区的 StatusBar，将健康状态与恢复操作收纳到已有侧栏状态区域。范围是该状态条及其重检入口，不扩展为整个页面的提示系统重构。

1. 删除 AppShell 两个分支中的 StatusBar 挂载，使有会话和空工作区都不再出现这条横栏，也不保留其高度、边框或占位。组件无其他调用方后，删除其文件、导入以及 [index.css](../../../../src/client/index.css) 中专用的 `.status-strip` 规则，包括移动端规则；共享的 `.workspace-alert`、状态点和加载动画仍由各自使用处维护。
2. 复用侧栏底部现有连接状态区域。正常时维持紧凑的状态展示；异常或状态请求失败时显示可理解的原因并提供重检操作，继续调用已有的 `loadStatus(true)`，检测期间防止重复点击。侧栏目前未单独区分 `config_error` 和请求失败后的未知状态，迁移时补齐这些显示分支，避免错误地一直显示“正在检查 Hermes”。
3. 重检操作在桌面侧栏折叠时仍有可识别、可键盘操作的入口；移动端可从会话列表抽屉访问。正常连接下不因局域网 HTTP 标记重新增加中间横条，也不为移除横条引入新的定时健康轮询。
4. 保留初始化健康探测、发送就绪判断及后端状态 API，重检成功后沿用现有状态更新恢复发送。会话加载失败、SSE 重连或事件缺口、发送失败等提示各自属于独立链路；输入区已有的异常说明继续帮助用户理解发送为何不可用。

预计实现范围为 AppShell、侧栏状态区域、StatusBar 和专用样式，不需要更改数据库或 Hermes 协议。这延续[移除冗余设置入口的界面简化方向](../../implemented/feature/2026-09-24-remove-settings-fix-sidebar-and-add-rename.md)，并按[清理未使用路径的决定](../../implemented/simplification/2026-09-25-remove-unused-paths-and-build-artifacts.md)清除不再调用的组件。落地时更新[架构文档](../../../../docs/01-architecture.md)中的组件图和[客户端文档](../../../../docs/06-client-internals.md)中的状态展示、重检入口说明；当前文档先保持现状。

## Alternatives considered

- **只让健康状态忽略局域网 HTTP 标记，异常时保留中间状态条**：改动最少，也能消除用户所述的“在线”一行；但中间仍保留同一条横栏的异常分支，不符合将这行从会话区移除的需求。
- **直接删除状态条，不保留页面内重检**：界面和代码都更少，整页刷新仍能重新探测；但异常恢复要中断当前页面，而且发送按钮不会因上游恢复自动解禁。侧栏已有合适的状态区域，保留一个紧凑的恢复入口成本更低。

## Acceptance criteria

- 在已选中会话、空工作区及桌面、移动端布局下，中间不再展示该状态条或留下空白占位；`healthy` 且 `lan_http_warning = true` 时也如此。
- 连接正常时，聊天、发送和草稿保存沿用现有行为；连接异常、配置错误或首次状态请求失败时，侧栏提供明确状态及可用的重检入口。
- Hermes 恢复后，通过侧栏重检即可更新状态并恢复发送，无需整页刷新；重检失败保留重试能力和用户已有草稿。桌面折叠侧栏及移动端抽屉都能完成此操作。
- SSE 重连、事件缺口及会话加载失败的提示仍能独立工作；删除组件后没有残留导入或专用样式。
- 实施后检查类型、lint 和前端构建，并手动检查布局与健康状态恢复。按 [AGENTS.md](../../../../AGENTS.md) 不新增“某段文字或按钮消失”的静态组件测试；若需补自动化用例，只验证异常重检后恢复发送且草稿不丢失的关键交互。

## Risks

- 重检移动到侧栏后，在折叠或移动端布局中的发现成本会上升；需明确入口的可访问名称及检测反馈，不能仅让不可交互的状态点承担恢复操作。
- 侧栏目前只接收状态字符串，迁移时需补充加载状态、回调及必要的异常信息。应传递明确的组件属性，避免侧栏自行维护第二份健康状态或重复发起探测。
- 移除整条 StatusBar 也会移除其中的缺失能力数量提示；需要诊断的异常信息应在侧栏状态区域可读，避免只剩“发送不可用”而没有原因。服务端局域网 HTTP 标记的含义和 API 字段不因这次展示调整而改变。
