# Agent Note: 工具调用展示轻量化

Status: proposed

## Problem

用户在 2026-10-07 采纳[对话展示调研](../../../research/2026-10-07-chatgpt-conversation-ui.md)中的方向，并确认理解工具展示的具体方案。现有工具调用默认虽折叠，但每次都有完整边框、背景和状态胶囊，连续调用占用较多阅读空间。

## Proposal

首期采用紧凑、可展开的工具状态行，保留真实工具名，不恢复参数摘要。运行时显示小型活动指示，成功状态弱化，失败醒目并默认展开。展开区保留脱敏输入、输出；长结果先显示有限内容，再主动查看完整内容。保留用户展开状态和现有实时到历史的稳定交接。

首期不合并多次调用，不移动正文、思考、工具或图片的相对顺序。工具图片结果独立于详情折叠，采用[生成图片方案](2026-10-07-generated-image-result-cards.md)。承接[工具名决定](../../implemented/feature/2026-09-25-tool-name-only-card-header.md)及[交接决定](../../implemented/feature/2026-09-24-progressive-tool-events-and-stable-run-handoff.md)。

## Alternatives considered

- 保留完整卡片、仅减少内边距：改动最少，但连续重复边框和成功胶囊仍突出。
- 首期直接合并全部工具调用：更省空间，但可能重排穿插正文并破坏展开状态，先保留逐项展示。

## Acceptance criteria

- 工具名、运行/完成/失败/待核对状态容易辨认，折叠时占用更少空间。
- 输入输出仍可查看，长结果可完整展开，失败不被折叠隐藏。
- 流式、历史补读、同名并发及跨会话切换继续遵守已有配对和隔离边界。
- 深浅主题、触屏和键盘聚焦可用，减少动画偏好生效。

## Risks

展开及长输出展示需要保持稳定身份，不能因终态交接丢失用户选择；淡化成功状态不能降低文字可读性。必要验证沿用跨模块交接及状态一致性用例，不为静态样式补测试。
