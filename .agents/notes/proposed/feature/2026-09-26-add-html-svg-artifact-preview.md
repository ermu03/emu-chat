# Agent Note: 增加 HTML 与 SVG 成果预览面板

Status: proposed

## Problem

用户希望 emu-chat 增加既实用又有趣的功能，并认可“聊天生成作品 → 打开操作 → 继续修改 → 下载保存”的成果预览流程。例如让 Hermes 生成番茄钟、单词测验、预算计算器或页面原型后，可以直接查看效果，而不必先复制代码到其他工具。用户也经常通过其他 AI 网页生成 SVG 小图标，希望在 emu-chat 获得同样的“生成 SVG 代码并直接预览”体验，因此 SVG 与 HTML 同属首版范围。

当前 [MessageView](../../../../src/client/features/messages/message-view.tsx) 使用 React Markdown 展示消息，代码块支持语法高亮和复制，没有独立的作品预览入口。[AppShell](../../../../src/client/app.tsx) 将队列面板放在输入框上方，尚无右侧成果区域。用户同时希望会话区保持简洁，新增能力应按需展开。

基于 emu-chat `f0e0619` 的代码检查，本提案不假设 Hermes 已提供成果文件或版本 API。根据[项目定位](../../../../docs/00-overview.md)，Hermes 继续持有权威消息历史，emu-chat 不另建完整聊天内容副本。

## Proposal

第一版支持助手回答中的两类成果：单文件 HTML 网页，以及独立 SVG 图标/矢量图。HTML 允许内嵌 CSS、JavaScript 和数据；SVG 按图片预览。两者共享预览、查看源码、复制与下载的入口，但使用各自的渲染方式。典型操作是生成一个番茄钟，点击开始和暂停，再回到聊天要求增加休息按钮，打开新回答中的完整文件查看修改效果。

### 1. 识别成果与展示入口

- 只从 Hermes 已保存的助手正文识别已闭合的代码围栏。`html` 围栏内的完整 HTML 文档进入网页预览；`svg`、`xml` 或 `html` 围栏中的内容，只有解析后确认为完整独立 SVG 根元素时才进入 SVG 预览。普通 XML、HTML 片段和未标记代码仍按原方式展示，不自动补全。完整 HTML 页面里的内嵌 SVG 属于该网页，不再单独拆成成果。
- 基于 Markdown 解析节点提取代码原文，在高亮处理之前取得文本；不从高亮后的 DOM 反向拼接，也不对整个回答用宽泛正则猜测文件边界。需要校验围栏闭合，因为 Markdown 解析器可能将未闭合围栏也解析为代码块。
- 每个符合条件的代码块提供紧凑成果入口，包含名称、“打开预览”、“查看源码”和“下载”。名称可来自 HTML 文档的 title 或 SVG 根元素的直接 title 子元素，缺失时分别用“HTML 成果”或“SVG 图标”；名称只按纯文本显示，文件名去除路径和非法字符。
- 默认不挂载 iframe，不自动运行脚本，不自动弹出面板。流式输出及尚未与历史核对的内容继续作为普通代码展示，待完整权威消息到达后才允许打开 HTML 或 SVG 预览。用户消息、工具输出及 reasoning 内容不自动获得执行入口。
- 多个 HTML 或 SVG 文档分别作为独立成果，不把同一回答中的 HTML、CSS、JavaScript 代码块自动拼装。第一版支持的是自包含文件，不承诺 CDN、外部图片、接口请求或 npm 依赖可用。

### 2. 面板与聊天操作

- 桌面宽屏点击后在聊天右侧打开成果面板，顶部显示名称、类型、预览/源码切换、复制源码、下载及关闭；HTML 另提供重新运行。关闭后恢复聊天区域宽度；当前输入框与队列面板保持原有功能和位置。
- 窄屏和手机端使用覆盖式全屏面板，明确提供返回聊天的入口。打开、关闭或响应式布局切换不卸载草稿编辑器，不清空草稿，不重置聊天滚动位置。键盘可以关闭面板，关闭后焦点返回触发入口；审批弹窗保持可见且可操作。
- SVG 预览提供适应面板、放大/缩小、重置缩放，以及透明棋盘格、浅色、深色背景切换，便于检查图标边缘和透明区域；默认按 viewBox 或有效尺寸保持比例，不拉伸图形。背景与缩放只影响观察方式，不改写或导出到 SVG 源码中。
- 同时只挂载一个成果预览，HTML 使用 iframe，SVG 使用图片元素。切换成果、切换会话、删除所属会话或关闭面板时销毁旧运行实例并释放临时 URL；仅切换预览/源码标签不无故重启当前实例。会话切换后不保留另一个会话的作品冒充当前成果。
- 预览始终运行用户选中的完整代码快照。新消息和 SSE 增量不会自动替换正在试用的作品；用户主动打开新的成果或点击重新运行才创建新实例。计时器进度等作品内部状态只在该实例存活期间保留。
- 继续修改使用现有聊天和草稿流程，不增加自动发送。用户可要求 Hermes“输出修改后的完整单文件 HTML”或“输出完整 SVG”；新回答提供新成果入口，旧回答中的成果仍可打开。

### 3. 数据归属、源码与下载

- 第一版不新增成果正文数据库、上传接口或服务端文件读取接口。成果由当前加载的权威消息派生，面板状态由独立前端模块持有，AppShell 只负责布局与打开/关闭的组合。
- 成果引用包含本地会话 ID、消息所属的有效 Hermes 会话 ID、消息 ID 和代码块位置；运行快照额外记录内容标识，以免历史分页、消息归并或流式交接将同一块代码重复识别，或把更新内容静默套入旧实例。
- 源码视图、复制和下载使用同一份从消息中提取的文本，并保留 SVG 的 viewBox、路径、渐变、遮罩等内容，不做自动优化或改色。当前消息 API 存在展示脱敏，成果也沿用该边界，不另开读取未脱敏原文的通道。预览运行时添加的隔离包装不混入用户下载的文件。
- 下载由父页面的明确操作按成果类型生成 `.html`（text/html）或 `.svg`（image/svg+xml）文件，不向 iframe 授予下载权限。刷新页面后，用户从相应消息再次打开；较早成果随“加载更早历史”出现，不承诺第一版拥有覆盖所有历史的成果目录。
- Hermes 若只回复服务器文件路径或“文件已生成”，仍按普通消息处理；不据此读取服务器目录，也不把文件路径当作可执行 URL。

### 4. 隔离运行与可用范围

生成的 HTML 和 SVG 均按不可信内容处理。以下是实现必须验证的边界，不是已经实现的安全保证。HTML 路径：

- 在独立的 sandbox iframe 内渲染，允许必要的脚本执行，但不授予 `allow-same-origin`、顶层导航、弹窗、表单提交、下载等权限；不在主页面使用原始 HTML 注入或 eval。页面内容不得读取父页面 DOM、存储或调用宿主的操作桥接接口。
- 使用应用控制的 CSP 限制执行环境：允许自包含作品所需的内联样式与脚本，阻止外部脚本、外部资源、网络连接、嵌套框架及插件，禁止 base URL 重定向和表单提交。策略必须先于成果内容生效，不能依赖成果自身提供 CSP，也不能只依赖实验性 iframe 属性。
- 无须向作品注入会话历史、草稿、凭据或 Hermes 地址，也不提供父页面 API 代理。首版不为功能报错而自动放宽外部资源权限。
- sandbox 和 CSP 不等同于完整的网络或 CPU 隔离。尤其需要验证 iframe 自身导航、meta refresh、链接和脚本跳转：限制父页面访问与 fetch，并不自动保证“绝不向外发送请求”。实施前对这类路径做浏览器验证，明确支持范围及剩余限制；若边界不能满足要求，应先收窄可执行内容或调整隔离方案，不能宣称完全离线或完全安全。
- 面板外壳始终保留关闭和重新运行入口。执行报错、外部依赖受阻时允许查看源码和下载，不自动重跑。对代码大小设定明确上限并与消息响应限制协调；过大内容回退为普通代码展示。iframe 无法保证终止所有死循环，不能把宿主定时器描述成可靠的 CPU 超时机制。

SVG 路径采用 `image/svg+xml` Blob URL 加 `<img>`，不使用 innerHTML、内联 SVG 注入、object、embed 或可执行文档 iframe。进入预览前以 XML 解析验证根元素及 SVG 命名空间，拒绝解析错误、DOCTYPE 和实体声明；不自动修补缺失结构，失败时保留源码与下载，并提示生成完整独立 SVG。脚本、事件处理及外部资源不作为支持能力，使用图片上下文的浏览器限制，并以真实浏览器验证；SVG 中的本地片段引用（如渐变、clipPath、mask、use）应正常保留。SVG 不能继承 emu-chat 的 CSS 或主题，currentColor 等默认颜色由图片文档自身决定，背景切换不等同于修改图标颜色。

浏览器行为参考 MDN 的 [iframe sandbox 说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)、[CSP 说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)及 [SVG 图片上下文说明](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image)。实施时需在实际目标浏览器验证，不能仅凭属性字符串或 jsdom 测试确认隔离有效。

### 5. 版本功能与实施范围

第一版每个代码块都是独立成果，只显示来源，不自动标记“第 1 版、第 2 版”。用户可以从先后两条消息分别打开旧、新结果。后续若增加版本切换，应先定义明确的作品身份和修订关联，不能把所有后续 HTML/SVG、相同标题或相似内容都认作同一作品的新版本。

本次范围不包括多文件工程构建、React/Vue 编译、依赖安装、服务端代码执行、源码在线编辑、SVG 可视化编辑、PNG 栅格导出、发布网站或完整成果库。后续可在首版使用反馈基础上扩展 Markdown、图像导出和明确的版本管理。

预计改动集中于消息渲染、成果提取与运行组件、AppShell 布局和[样式](../../../../src/client/index.css)。成果提取应保留[消息分组](../../../../src/client/features/messages/message-display.ts)中的原消息身份，避免只在通用 Markdown 组件内新增状态、丢失角色和来源边界。与[会话状态隔离提案](../architecture/2026-09-26-guard-conversation-view-updates.md)保持一致，不扩大跨会话状态回写面。实施后更新[客户端说明](../../../../docs/06-client-internals.md)、[安全说明](../../../../docs/09-error-and-security.md)和 README，并将本笔记随代码移入 implemented；提案阶段保留现状文档。

## Alternatives considered

- **继续只提供代码复制和下载。** 实现最小，适用于需要在编辑器中开发的项目；但无法满足用户直接操作作品、边看边通过聊天修改的体验，因此增加按需预览。
- **在消息流里自动渲染或执行所有成果。** 结果最直观，无须点击；但不完整的流式代码会反复重启，多个运行实例增加资源占用，也让用户阅读普通回答时被动执行脚本，因此采用主动打开、单实例运行。
- **读取 Hermes 生成的服务器文件。** 能覆盖真实项目和工具写出的文件；但需要文件归属、读取权限、路径限制和文件生命周期约定，当前消息接口无法直接提供。首版从消息中的自包含文件起步。
- **直接加入在线 IDE 和自动版本树。** 能支持复杂项目及持续迭代；但同时引入构建、依赖和版本身份问题。先验证预览与下载的价值，再决定是否扩展。

## Acceptance criteria

- Hermes 返回完整单文件番茄钟后，普通聊天保持原布局；用户点击才打开预览，开始、暂停和重置正常，关闭后能继续聊天，下载文件包含同一份成果源码。
- 完整 SVG 图标可以打开预览，viewBox 比例、路径、填色、描边、渐变和内部引用正常；缩放、适应面板及背景切换生效，复制和下载仍保留原始 SVG 文本，下载文件可在支持 SVG 的工具中打开。
- 未闭合围栏、普通 XML、无效 SVG、其他语言代码、用户消息、工具输出和流式片段不触发预览执行。一个回答中的多个 HTML/SVG 文档可以分别选择，普通代码复制与高亮行为不回归。
- 后续回答生成新的完整 HTML 或 SVG 时，当前实例不自动切换或重启；新旧成果可以从各自消息打开，历史分页和实时转权威消息不产生错误关联。
- 打开、关闭、切换源码、手机返回及切换会话均不丢失草稿；离开所属会话会销毁旧实例，审批和队列操作仍可使用。
- 在目标桌面及移动浏览器确认预览无法读写父页面 DOM/存储，不能打开弹窗、导航顶层页面或调用宿主 API 代理；外部资源和网络连接按策略被阻止，并实际检查自身导航等剩余路径，将验证结果及限制记入落地笔记。
- SVG 图片中的脚本和事件处理不执行，外部脚本、图片、样式及字体不发起加载；本地片段引用仍可显示。检查解析失败、缺失有效尺寸和高复杂度图形的回退体验，不能只验证一个简单图标。
- 无外部依赖的 HTML/SVG 文件下载后可独立打开；下载不混入预览包装或棋盘格背景。下载文件在浏览器中独立打开时不再享有面板的完整隔离环境，SVG 直接作为文档打开也不同于图片上下文，界面用简短说明交代运行环境差异。
- 实施时通过类型检查、Lint 和构建；用真实浏览器验证交互与隔离。按 [AGENTS.md](../../../../AGENTS.md)避免静态文字、按钮和普通 getter 测试；自动化优先覆盖跨会话异步隔离与草稿不丢失，安全边界用针对性浏览器验证，不把 jsdom 结果当作执行隔离的证据。

## Risks

- 服务端展示脱敏可能改变内嵌代码，导致作品运行不正常；必须保留现有脱敏边界并允许查看实际收到的源码，不能为了预览另取含敏感内容的原文。
- 部分生成结果可能依赖 CDN、持久化存储、外部字体/图片或接口，与首版自包含范围不符。面板应说明依赖限制，不能自动补装依赖或接入真实业务接口。
- iframe 和复杂 SVG 均会消耗浏览器资源，异常脚本或大量路径/滤镜可能影响页面响应；单实例、主动运行和体积限制减少风险，但不构成 CPU 配额或完整网络沙箱。
- 消息切换与终态历史交接已有复杂状态，成果模块必须使用明确来源和选中快照，避免新结果覆盖用户正在试用的旧结果。
- 第一版不自动关联跨消息版本，也不保存作品运行状态；清楚区分“生成的新代码”与“正在运行的旧实例”，后续版本功能需要独立确认数据约定。
