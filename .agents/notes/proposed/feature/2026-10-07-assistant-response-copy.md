# Agent Note: 助手回复与代码复制操作

Status: proposed

## Problem

用户采纳[对话展示调研](../../../research/2026-10-07-chatgpt-conversation-ui.md)中的回复操作方向。现有助手回合缺少整段复制；普通代码有复制，可预览成果则用预览按钮替代复制。复制失败目前没有明确反馈。

## Proposal

助手回合底部提供小型复制入口，复制按显示顺序组成的助手正文，保留 Markdown 和代码围栏；不包含思考、工具日志、状态提示或图片机器清单。正常复制在回复结束后开放，停止后的已有文字也可复制。触屏入口直接可用，桌面悬停/键盘聚焦可以增强显示；提供成功与失败反馈。

代码块复制只取原代码，同时提供复制与预览。处理 Clipboard API 不可用的手动选择备用入口，延续成果预览的来源验证与执行边界。与[工具展示](2026-10-07-lightweight-tool-display.md)分离正文及日志复制。

## Alternatives considered

- 直接复制整行 DOM 文本：实现简便，但会混入工具、按钮和状态文案，无法保持代码格式。
- 所有回复只提供原始 Markdown 下载：便于保留格式，但增加日常复制的操作成本。

## Acceptance criteria

- 回合复制保持正文顺序与代码内容，不夹带技术日志、思考或界面文案。
- 代码块可同时复制和预览；原有预览准入及 sandbox 行为保持有效。
- 复制成功才显示成功反馈；失败或 API 不可用时有可操作的提示。
- 移动端、键盘聚焦以及跨会话后的迟到回调不会错误更新当前操作反馈。

## Risks

回合有多个文字段时需定义组合规则，避免重复文字；流式文本和权威历史校正不能让复制目标身份串到其他回合。验证只覆盖来源一致性和关键异步交互，样式用本地预览检查。
