# Agent Note: 生成图片结果卡片与阶段反馈

Status: proposed

## Problem

用户采纳[对话展示调研](../../../research/2026-10-07-chatgpt-conversation-ui.md)中的图片展示方向。现有生成结果与上传附件共用 126px 缩略图；资源出现前没有图片占位，保存状态与模型生成阶段的反馈不完整。下载、复用需先打开查看器。

## Proposal

为生成结果设置独立大图布局，桌面单图最大宽度从约 400–480px 起步，窄屏自适应，保留原图比例，多图使用网格；上传附件保留紧凑展示。结果旁提供下载与“用于下一条消息”，点击图片沿用大图查看器，技术详情单独折叠。

已明确识别生图工具开始时提供保守尺寸的占位，区分正在生成、正在保存、已就绪、生成失败、保存失败、暂不可用及待核对。使用不定进度反馈，不编造百分比或预览。权威图片就绪后尽量原位替换，延续[图片补读修正](../../implemented/bug-fix/2026-09-30-complete-generated-image-refresh-and-recovery.md)。同名并发仍待权威历史配对，保存重试不重新调用付费模型。

## Alternatives considered

- 把所有附件缩略图放大：最少组件改动，但输入区和队列附件也会显著挤占空间。
- 生图结果只放进工具详情：结构简单，但用户必须展开技术记录才能查看主要结果。

## Acceptance criteria

- 单图、多图和等待状态在深浅主题、窄屏中清晰可用；生成结果不随工具详情折叠消失。
- 下载与复用入口直接可用，复用只追加草稿，不自动发送。
- 真实状态与提示一致；没有准确调用身份时不猜测归属。
- 实时/历史交接、保存失败重试及跨会话切换不串图、不丢失已显示结果。

## Risks

无稳定工具调用 ID、资源采集延迟和未知图片尺寸会限制占位精度；必须保留已有异常恢复及权限边界。用隔离工具事件和图片 fixture 验证必要链路，无需真实付费调用。
