# Agent Note: 按助手回合折叠工具调用与思考过程

Status: proposed

## Problem

原 BUG-3：[getRenderableMessages](../../../../src/client/features/messages/message-display.ts) 只过滤空消息，[MessageView](../../../../src/client/features/messages/message-view.tsx) 按消息逐条渲染。一次回答包含多个工具调用时，工具请求和结果会占据大量独立气泡，最终回复不容易阅读。

## Proposal

在展示层将连续的助手交互整理为可辨认的回合：最终回复保持展开；思考过程和工具调用可按需展开查看，工具结果与对应调用关联。保留消息原始顺序和身份标识，不改变 Hermes 的存储格式或前后端消息协议。分组边界须覆盖没有最终文本、工具失败以及正在流式生成的情况。

## Alternatives considered

- **继续逐条展示**：原始消息最透明，实现也最简单；工具密集的会话会遮住主要对话。
- **只折叠单条工具气泡**：改动较小；一次回答仍会留下多个分散的工具入口。
- **按回合聚合**：阅读路径最清晰；需要准确识别助手、工具结果和下一条用户消息之间的边界。

## Acceptance criteria

- 多次工具调用的回答默认突出最终回复，并能展开查看每次调用及结果。
- 普通对话、无最终文本的回合、工具失败与流式状态都不会丢失内容或错配工具结果。

## Risks

Hermes 消息不一定天然对应单一 UI 回合；需要用真实消息序列验证边界，避免把相邻但无关的消息合并。
