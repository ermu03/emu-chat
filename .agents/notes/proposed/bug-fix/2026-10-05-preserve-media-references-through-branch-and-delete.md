# Agent Note: 分支与删除过程中的图片引用保护

Status: proposed

## Problem

本篇安排在草稿、会话清理和停止暂停保护之后。2026-10-05 的内存 SQLite 与模拟插件复现确认了两个图片关联缺口。

其一，[MediaBranchService](../../../../src/server/media/branch.ts) 的 A→B 分支产生 1 条输入图片映射，但 B→C 分支产生 0 条映射并被标记为完成。复制到 B 的用户消息仍带 A 的原始清单，当前分支只接受 scope 属于直接来源 B 的清单，没有读取 B 已验证的 `media_branch_messages`。工具图片还按原始资源的来源 session 过滤，需要一并覆盖继承的输出图片。

其二，[MediaSyncWorker](../../../../src/server/media/sync.ts) 在会话 `delete_state` 不为 `none` 时，把尚未执行的普通同步任务直接标成 `done`。隔离复现中，删除因 Hermes 忙碌而撤销、会话恢复可用，但引用写入调用次数为 0，任务已完成且无法重试。分支 `sync` 遇到目标临时删除状态也会提前返回，其调用方随后标记完成；这一并发路径需在实施时补齐验证。

这些问题共同违反[图片工作流决定](../../implemented/feature/2026-09-28-add-image-workflows.md)和[图片规格](../../../specs/2026-09-28-image-workflows.md)中的约束：关联完成前保护来源，临时故障后继续同步，确认删除后才释放引用。文本保留期限另由[正文清理提案](2026-10-05-clear-frozen-queue-payloads.md)处理。

## Proposal

1. 分支关联先按权威复制消息配对，并读取直接来源会话已验证的分支映射。继承图片从直接来源 scope 的有效权限授予目标 scope，保留原 operation 关联；来源自身的新消息继续走原清单绑定或工具来源验证。不得凭原始清单中其他 scope 的 ID 直接扩大权限。
2. 对继承输入图和工具输出图都建立目标消息映射与分支引用。只关联实际复制消息涉及的资源，逐项验证目标授权和引用成功，再提交本地映射与完成状态。跨服务调用保持幂等，失败后可沿原任务重试。
3. 普通 outbox 和分支 worker 显式区分完成、延期与目标已确认删除。`pending`、`failed` 等删除暂态保持任务可恢复，安排后续尝试并允许其他 scope 的任务前进；目标确实已删除时才结束失去用途的普通关联任务，scope 删除任务继续按现有持久重试流程执行。
4. 网络等待后、提交关联结果前复核目标状态。关联未确认完成时继续保护来源；删除撤销后按原任务恢复，不能把跳过一次执行当作成功。确认删除依赖[会话安全清理](../../implemented/bug-fix/2026-10-05-safe-conversation-list-and-cleanup.md)的条件删除结果。
5. 沿用独立插件、不可变原件、消息身份配对、持久 outbox 与删除墓碑边界。实现时更新[图片维护说明](../../../../docs/11-image-workflows.md)、[服务端说明](../../../../docs/04-server-internals.md)，并关联图片工作流决定的后续修正。

## Alternatives considered

- **对分支复制来源 scope 的全部资源授权**：实现简单，能避免清单仍指向更早 scope 时漏图。但会授予实际没有复制的消息或来源未来消息的图片，破坏分支权限边界。
- **删除开始时就结束普通同步任务**：可减少对即将删除 scope 的无效请求。但删除可能因健康检查、忙碌或网络失败而撤销，必须保留暂态期间的恢复能力。
- **删除撤销后重新全量扫描并重建引用**：可补偿部分丢失关联。但来源和关联身份可能已变化，且需要额外扫描和未知引用的处理；保留原持久任务更容易维持幂等与来源证明。

## Acceptance criteria

- A→B→C 连续分支保留实际复制消息的输入图和工具输出图，映射关联到各自的新消息 ID；其他未复制消息的图片不被授予。
- A→B 完成后删除 A，B 仍可使用自己的图片，并可继续分支给 C；删除某个会话不影响其他有效引用。
- 目标删除处于暂态时，普通 outbox 和分支任务保留可恢复状态；删除撤销或重试恢复后，原任务继续执行且不会误报完成。
- 授权或引用写入失败、插件离线及服务重启后，可以幂等恢复；完成前来源保护持续有效，确认完成后才解除相应阻断。
- 目标最终删除时，scope 删除任务保留持久重试能力；迟到关联回调不能复活本地会话或已撤销的 scope。
- 在[分支恢复测试](../../../../tests/unit/media-branch-recovery.test.ts)和[图片主干集成测试](../../../../tests/integration/media-run-flow.test.ts)中补必要的继承、失败和删除撤销场景，按[AGENTS.md](../../../../AGENTS.md)验证引用一致性及异步提交边界。

## Risks

- 权限、引用与本地映射跨两个服务，无法原子提交。幂等请求、完成标记和来源保护必须覆盖部分成功后崩溃的情况。
- 原资源来源信息不应随分支改写。继承需要区分原始来源与直接来源 scope 的使用权限，否则可能漏掉有效资源或错误授权。
- 延期任务不能在每次 worker 循环占住首项，需通过合理的下次尝试时间或任务选择继续推进其他 scope。
- 删除临时失败和最终确认删除必须有明确判断依据。关联身份不确定时保留资源和待核对状态，避免提前释放。
