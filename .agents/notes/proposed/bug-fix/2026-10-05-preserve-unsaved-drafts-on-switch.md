# Agent Note: 切换会话时保留未保存草稿

Status: proposed

## Problem

本篇优先实施。2026-10-05 对开发目录的隔离组件复现确认：在会话 A 输入文字，500ms 防抖结束前切到 B，再返回 A，保存调用次数为 0，输入框恢复为空。保存失败后再切换也缺少未保存输入的可靠存续路径。

[DraftComposer](../../../../src/client/features/composer/draft-composer.tsx) 独占未保存正文、附件与保存队列，切换会话和卸载时取消防抖，切换后重置为服务端草稿。[useConversationView](../../../../src/client/state/use-conversation-view.ts) 的会话缓存保存的是已提交草稿，不能恢复组件刚丢弃的输入。现有[视图隔离决定](../../implemented/architecture/2026-09-26-guard-conversation-view-updates.md)解决了旧响应污染当前视图，但没有覆盖未保存草稿跨组件生命周期的保留。

同一输入链路还有较小的误发送问题：组合输入中的 Enter 没有检查 `isComposing` 或输入法兼容信号。隔离复现中，`isComposing=true`、`keyCode=229` 的 Enter 调用了发送一次。本篇一起处理这一输入保护，不另立提案。

## Proposal

1. 将未保存正文、已就绪附件、已保存 revision、待保存快照及保存错误按会话保留，存续期覆盖输入框切换与卸载。沿用现有视图 Hook 的状态归属，明确草稿状态的唯一所有者，避免组件和缓存各自维护会互相覆盖的输入副本。
2. 切换时保留源会话快照并推动源会话保存，进入目标会话时立即恢复其未保存输入或已保存草稿。每个会话的保存保持单飞；待保存队列使用固定源会话 ID 和对应 revision，不在回调完成时重新取当前选择。
3. 保存确认只推进它实际保存的快照与 revision。期间的新输入继续保留并排队保存；保存失败或 CAS 冲突保留本地内容及可重试状态。当前视图写入继续核对 `ViewTarget`，后台草稿保存的存续不能成为绕过选择代数的入口。发送仍先等待该会话的草稿保存成功。
4. 输入法组合输入及其确认 Enter 不触发发送；普通 Enter、Shift+Enter 与配置的组合发送快捷键保持各自语义。实现时更新[客户端说明](../../../../docs/06-client-internals.md)、[草稿数据流](../../../../docs/07-data-flow.md)，并关联视图隔离决定中草稿存续边界的后续调整。

## Alternatives considered

- **切换前等待当前 `flushDraft` 成功**：可以复用现有保存队列和 CAS，状态改动较少，也能明确避免离开未保存输入。但断网或保存冲突会阻塞会话切换，与[缓存秒开决定](../../implemented/bug-fix/2026-09-23-smooth-conversation-switching.md)的体验目标相冲突，选择按会话保留并后台保存。
- **只在卸载时补一次保存**：实现范围小，能缩短防抖造成的遗漏窗口。但网络失败后组件已离开，输入与错误仍没有可靠的恢复入口，A→B→A 时旧保存与新输入的关系也没有解决。

## Acceptance criteria

- 输入后 500ms 内 A→B→A，正文及已就绪附件仍在，源会话保存最终可完成，B 的草稿不受影响。
- 保存失败或版本冲突后可以切换会话；回到源会话仍能看到未保存内容并重试，不能静默覆盖服务端较新草稿。
- 源会话保存延迟返回、连续切换和再次编辑时，旧确认不会覆盖当前输入；保存完成后继续提交较新的快照。
- 脏草稿不会因普通会话视图 LRU 淘汰而被丢弃；成功保存、用户明确清空或会话确认删除后才结束相应存续状态。后台保存不能复活已删除会话。
- 发送先保存正确会话的完整快照，发送失败保留输入；输入法确认键不调用发送，正常发送快捷键仍可用。
- 在[跨模块组件测试](../../../../tests/components/app-shell-flow.test.tsx)和[高风险输入交互测试](../../../../tests/components/react-components.test.tsx)中补充必要的切换、失败与旧响应场景，按[AGENTS.md](../../../../AGENTS.md)验证并同步受影响文档。

## Risks

- 状态从组件存续期延长到会话存续期后，保存确认、发送清空和再次输入的边界需要统一；两份竞争的脏状态会引入更难发现的覆盖问题。
- 保存未成功的草稿可能超过现有视图缓存容量，需要保护脏数据并在成功后释放，避免长期内存增长。
- 本篇保证页面内会话切换时的输入存续；浏览器刷新以已保存草稿为准，尚未上传完成的原始 File 恢复沿用[图片规格](../../../specs/2026-09-28-image-workflows.md)，不得显示为已经保存。
- 现有 `ViewTarget`、草稿 CAS 和[发送前保存约定](../../implemented/bug-fix/2026-09-24-save-prompt-starter-draft.md)仍是约束。调整状态归属时应保留这些保护，避免扩大为整个客户端状态重构。
