# Agent Note: 手机输入区紧凑布局与可见视口适配

Status: proposed

## Problem

2026-10-07 用户反馈手机 Edge 中底部输入区占据很大空间，聊天文本可见区域狭窄。当前结论来自源码分析，尚未进行真机复现；手机系统与浏览器具体版本仍待补充。

[DraftComposer](../../../../src/client/features/composer/draft-composer.tsx) 的高度脚本仍限制在 84–230px，手机 CSS 的 76px 最小高度不能使实际输入框低于脚本下限。加上 46px 按钮栏、边框和手机外层底部 12px 留白，空白正常输入区约 144px 高（代码估算，不是真机测量）。聊天列表另有 150px 底部 padding，在已有独立输入区占位的布局中增加重复留白。附件、队列与暂停恢复面板均在输入区附近继续增加高度。

应用以全高 flex 布局常驻底部输入区，只有消息区滚动；页面使用 `height:100%` 和隐藏 body 溢出，未按可见视口专门处理软键盘。键盘对可见视口及布局视口的影响随浏览器而异，不能仅把某一浏览器默认行为当作所有手机行为。依据：[VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)、[viewport 配置](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport)、[Chrome 键盘视口说明](https://developer.chrome.com/blog/viewport-resize-behavior)。

## Proposal

1. 手机输入区从单行起步，添加图片、输入、发送共用紧凑一行；正常空白/短输入整体目标约 56–72px，系统安全区另计。按内容增长，上限约 100–120px，并随当前可见高度降低；超出后正文在编辑区内部滚动，避免输入无限挤占聊天。CSS 与高度脚本使用一致的响应式约束。
2. 移除手机常驻字节统计及物理键盘快捷键提示；接近上限或出错时仍显示明确提示、重试保存及冲突处理入口。正常保存反馈保持简短。发送点击目标和中文 IME 行为继续可用。
3. 取消手机聊天列表为输入区重复预留的 150px 底部空白，改为少量阅读间距。输入区仍使用独立布局占位，最新消息不被遮挡；改变输入高度、收放键盘时不把正在阅读旧消息的用户强拉到底部。
4. 附件采用单行紧凑预览；队列和暂停恢复默认显示状态摘要，主动展开详情。待核对状态、错误和必要操作入口仍明显，人工核对勾选、当前 Run 限制、恢复与复制的语义不变。
5. 以动态视口高度处理地址栏变化；支持的浏览器可使用 `interactive-widget=resizes-content`，可见区域仍不正确时由 `visualViewport` 尺寸与偏移补充。避免键盘高度重复扣减、浏览器自动平移与自定义平移叠加，以及把缩放误当键盘。处理安全区与横屏，键盘收起后恢复完整消息区域。

长文的独立扩大编辑入口可作为后续增强，首期不自动隐藏整个输入框、不因失焦或折叠销毁草稿组件。与[未保存草稿保护](../../implemented/bug-fix/2026-10-05-preserve-unsaved-drafts-on-switch.md)保持一致。本文承接[前端布局决定](../../implemented/feature/2026-09-24-refine-frontend-ui-aesthetics.md)，手机紧凑布局与桌面布局分别处理。

## Alternatives considered

- 输入区随全部聊天一起滚动：阅读时省空间，但发送需要找回入口，长会话中不便继续对话。
- 阅读时自动隐藏输入区：最节省屏幕，但容易受滚动、失焦、选中文本和键盘收放影响而跳动；先保持小型常驻输入入口。
- 只减少 CSS 最小高度：改动小，但脚本仍强制 84px，且不能解决额外底部留白、附件和软键盘视口。

## Acceptance criteria

- 手机空白或短输入比当前明显更矮，普通状态的消息区获得更多有效阅读空间。
- 多行及附件不无限增加底部占用，长输入全部保留且可编辑；发送、重试和冲突处理可用。
- 键盘打开、关闭，地址栏收放及横竖屏切换后，输入入口和最后消息均可到达，页面无永久空白或偏移。
- 队列、暂停、人工核对与恢复条件保留；不发生折叠后越过确认、自动发送或草稿丢失。
- 桌面原有编辑体验及跨会话隔离保持正常。按 AGENTS.md 只补必要的状态/异步验证；几何布局及真键盘行为通过浏览器和用户设备检查。

## Risks

可见视口 resize、scroll 与浏览器自动聚焦滚动可能交错；需要在实现时用实际 Edge/手机平台核验。模拟缩小窗口不能代替真机软键盘验证。当前没有真机证据，不宣称本方案已经消除 Edge 的实际问题。
