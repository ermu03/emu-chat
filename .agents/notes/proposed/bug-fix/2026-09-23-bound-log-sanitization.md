# Agent Note: 限制日志脱敏遍历的深度与循环引用

Status: proposed

## Problem

原 TASK-8：[sanitizeLogValue](../../../../src/server/logging.ts) 递归处理对象和数组，目前没有最大深度或循环引用检测。异常深的元数据可能导致栈溢出，循环引用也会让递归无法结束；日志记录本身不应让服务崩溃。

## Proposal

为遍历设置合理的最大深度（原设想约 8 层）并检测当前递归路径上的重复对象，超出限制时输出明确占位符。先执行现有的敏感键和内容字段脱敏，再决定是否深入子值；数组与对象都应适用同一边界。限制值和占位符可在实现时依据实际日志结构确定。

## Alternatives considered

- **维持无限递归**：完整保留普通嵌套对象；对非预期结构没有保护。
- **只加深度限制**：能挡住很深的无环对象；浅层循环引用仍会反复递归。
- **深度限制加循环检测**：覆盖两种失控情况，但部分深层调试信息会被截断。

## Acceptance criteria

- 过深或循环引用的 `details` 能被序列化为一条日志，而不会抛出或泄露未脱敏内容。
- 常见浅层日志保留现有字段与脱敏行为。

## Risks

简单的全局“已见对象”集合会把重复引用误判为循环；实现时应区分递归路径与可安全复用的对象。
