# Agent Note: 会话列表完整性与安全清理

Status: proposed

## Problem

本篇优先实施。2026-10-05 使用内存 SQLite 和模拟上游复现了旧查询误删：`listConversations` 等待旧 session 的详情期间，`getMessages` 已将同一会话采用为新 session；旧详情返回 404 后，本地会话与未发送草稿仍被删除。

[ConversationService](../../../../src/server/services/conversation-service.ts) 用查询前的会话快照调用 `removeMissingLocalConversation`；[ConversationRepository](../../../../src/server/db/repositories/conversation.repository.ts) 的删除只匹配会话 ID，没有复核查询时的 session 映射。删除还级联清理队列、Run、图片控制记录，并产生图片 scope 删除任务，因此列表刷新中的旧响应具有数据丢失风险。

同一列表链路还有完整性与读取成本问题：[AppShell](../../../../src/client/app.tsx) 只请求前 50 条并忽略 `has_more`，后端则在分页前串行查询所有注册会话。隔离数据包含 51 个会话时，首屏没有较旧的置顶会话，读取第一页仍调用上游 51 次；客户端没有取得该会话的后续页入口。补分页时必须同时考虑删除导致的边界移动及重复全扫描的成本。

## Proposal

1. 自动清理携带发起查询时的会话 ID 与预期 session ID，在同一个 SQLite 即时事务中复核当前映射并执行条件删除。映射已改变时放弃旧清理，按当前映射刷新或等待下一轮读取；SSE 清理和图片删除任务只随真正成功的本地删除提交。显式删除中的临时状态交由原删除流程处理。
2. 会话列表持续推进 `has_more` 所描述的分页范围，并按会话 ID 合并结果。保留置顶分组和本地排序语义，使第 50 条以后的会话及较旧置顶会话可访问。列表重载使用新的请求代数，旧分页响应不能回写另一轮列表。
3. 从本地注册集合确定待读取的页面范围，按需取得上游元数据并限制并发；清理无效项后正确推进或补齐页面。避免每翻一页先串行扫描整个注册集合。具体分页边界需结合现有排序核实；若 `offset` 在清理后不能可靠推进，同批调整私有分页 Schema、服务和客户端，并以 ID 去重和重新遍历达到完整结果。
4. 上游读取、重试与任何候选缓存始终受本地注册表约束，沿用[架构中的会话所有权边界](../../../../docs/01-architecture.md)。旧详情的元数据不能被拼接到新 session 映射上，也不能通过扫描上游所有会话自动导入其他客户端的会话。
5. 实现时同步[服务端说明](../../../../docs/04-server-internals.md)、[客户端说明](../../../../docs/06-client-internals.md)和[接口文档](../../../../docs/08-api-reference.md)。自动清理与[图片引用保护](2026-10-05-preserve-media-references-through-branch-and-delete.md)共用“确认删除后才释放资源”的边界。

## Alternatives considered

- **只在删除前再读一次映射**：改动少，能发现部分旧响应。但读取与删除之间仍可能发生映射变更，需要将复核与条件删除放在同一事务内。
- **保留后端全扫描，仅让客户端读取全部页面**：能快速恢复 50 条以后的会话入口，也保留当前按上游有效结果分页的方式。但每页重复查询全部注册会话，分页越多成本越高，清理与 offset 移动也仍需一起处理。
- **增加长期元数据缓存或优先接入上游批量接口**：可能进一步减少网络往返。但需要验证批量接口、缓存失效及所有权过滤；先实现按需分页和有界读取，额外缓存或批量能力作为实际查询成本仍过高时的候选。

## Acceptance criteria

- 挂起旧详情查询，采用新 session 映射后再返回旧 404，本地会话、草稿、队列与图片引用仍保留，不产生 scope 删除任务。
- 当前映射确实不存在且满足自动清理条件时，可完成幂等清理；重复响应或映射变化不触发错误的级联删除。
- 静态列表超过 50 条时可完整遍历，较旧置顶会话可选择；翻页、清理和列表重载交错后，通过去重与必要刷新得到完整列表。
- 旧分页响应不覆盖新一轮列表；同一会话不会重复出现，也不会把旧 session 的详情当成新 session 的元数据。
- 一页元数据读取与其页面推进范围相匹配，上游并发有界，后续页不要求重新串行扫描全部会话；任何实现都不能引入其他客户端的会话。
- 在现有[仓储并发测试](../../../../tests/unit/phase1-repositories.test.ts)、核心集成和[会话异步交互测试](../../../../tests/components/app-shell-flow.test.tsx)中补必要场景，按[AGENTS.md](../../../../AGENTS.md)验证事务、级联影响及列表可达性。

## Risks

- 本地记录顺序、上游存在状态和查询期间的映射都可能变化。按页读取不能假定简单累计已展示条数就是可靠的下一页边界，接口调整需与客户端同批落地。
- 限制并发有助于降低串行等待，但无限并发会冲击 Hermes；重试也必须有界。
- 自动清理具有不可逆的级联影响，需要把所有后续副作用绑定到条件删除结果，不能先清 SSE 或入队图片删除再判断条件。
- 新缓存会引入标题、置顶和映射的失效规则。本篇优先修复安全边界与可达性，具体缓存和批量能力在证据充分时再决定。
