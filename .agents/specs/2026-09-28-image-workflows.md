# 图片工作流实施规格

状态：提案配套规格，未实现。决策入口：[图片识别、生成与编辑提案](../notes/proposed/feature/2026-09-28-add-image-workflows.md)。

本文给后续编码模型交接：产品选择以提案为准，协议是准备实施的约定，不代表现有 Hermes 已有这些接口。P0 的验证结果应更新本文；无法满足既定边界时记录具体阻碍，不自行改 Hermes 核心或换一套 Run API。

## 1. 已定边界

- 现有聊天中上传图片并输入自然语言；识图、生成和编辑由 Hermes 及其已有工具处理。
- 图片加文字、多轮编辑；文件选择、粘贴、拖放；结果查看、下载、再次引用。仅附图但无文字可发送，桥接层使用固定、透明的默认识图要求，不默认执行编辑或生成。
- 默认一条消息最多 4 张静态 PNG/JPEG/WebP，单张上传最多 8 MiB。拒绝动图、SVG、GIF、HEIC 和损坏文件；说明原因，不静默取第一帧或转换有损格式。结果支持同样的三种静态位图，单张采集上限默认 32 MiB。默认像素上限 32 MP、单边上限 16384，均经实际解码验证；限制可由服务端配置并通过能力接口公开有效值。
- 4 张是附件存储上限，不是对所有供应商的多图承诺。显式暴露当前编辑支持的最大参考图数；工具调用超限时阻止静默截断，提示调整图片或配置。不同工具允许使用同一回合中不同的图片子集。
- 原样保存经验证的文件，保留透明度和元数据；缩略图只是派生资源，下载仍是原文件。首版不承诺移除 EXIF 或做隐私净化。图片 URL 不公开分享。
- 不增加模型选择 UI、画布编辑器、独立图库、对象存储服务、另一套模型任务队列或多实例高可用。
- 与 HTML/SVG 成果预览解耦：本功能只需要消息缩略图和大图查看器，不以另一个提案完成为前提。

## 2. 总体线路与模块

```text
浏览器 ──同源上传/图片读取──> emu-chat media service
                                  │ 私有服务凭据
                                  ▼
                           emu-media 资源接口 ──> 插件文件与索引

文字＋附件引用 ──> 草稿 ──> 现有队列 ──> Hermes /v1/runs
                                               │
                                   官方 Hook + 原有图片工具
                                               │
                        post_tool_call ──> 持久化采集任务
                                               │
                        历史对账补偿 ──> 采集并验证图片 ──> 稳定资源
```

插件持久目录 `$HERMES_HOME/emu-media/`，建议内部区分 `media.sqlite`、原文件、派生缩略图、临时文件。生产插件代码位于 `$HERMES_HOME/plugins/emu-media/`，两者不得嵌套。宿主 Python 环境沿用 Hermes；依赖尽量复用并声明兼容范围，不在加载 Hook 时临时安装软件。

emu-chat 增加独立的 media client/adapter、media service 与 media routes；不要让原来只处理 JSON 的 `HermesClient.request` 承载整个二进制协议。网络基础设施可适量复用。附件模型由 shared schema 定义，草稿和队列使用相同的有序资源引用结构。

## 3. 图片、引用与提交身份

至少区分四种身份，不把文件路径作为 ID：

| 身份 | 用途 |
| --- | --- |
| `asset_id` | 一份不可变的图片资源；内容摘要仅用于完整性与内部去重，不作为授权凭证 |
| `scope_id` | 一个 emu-chat 本地会话的资源范围，可使用其 `cv_` ID |
| `operation_id` | 一次队列提交，复用 emu-chat 已有 `op_` 标识 |
| 来源身份 | 上传 ID，或 Hermes `session_id`、`turn_id`、`tool_call_id` 及输出序号 |

资源与会话是多对多关系。文字草稿、队列恢复、历史消息、分支分别形成引用，文件是否可清理由所有有效引用共同决定。blob 去重不能导致不同会话越权读取，也不能让删除某一引用影响其余引用。

上传得到 `asset_id` 后，草稿只保存该资源的有序引用。重新引用已生成图片保持同一资源，不复制文件；再次编辑的结果生成新资源，旧图不变。输入图与输出图之间可记录来源关联，但首版不建立自动版本树。

插件建立本地 `scope_id` 与已验证 Hermes 会话 ID 的关联。emu-chat 读取历史得到 `effective_hermes_session_id` 后补登记别名；已有历史消息中的原会话 ID 必须保留。不能按标题匹配，不能把所有同一父会话的资源自动授予任意会话。

工具事件缺少足够来源时保留为待核对，不猜测最近会话。关联可在 pre_llm_call 建立的 turn 映射和权威历史中补齐。首版主要覆盖当前 Run 直接执行的图片工具；子代理输出只有来源可证明时才接纳，不承诺扫描其工作目录找图。

## 4. 插件 HTTP 契约

命名空间拟定为 `/v1/emu-media`，只作用于当前默认 Hermes profile。首版不实现多租户或跨 profile 访问。P0 固定请求/响应 schema 后，P1、P3 共享协议 fixture。

| 接口 | 责任 |
| --- | --- |
| `GET /capabilities` | 协议版本、图片功能状态、上传限制、工具输入桥接与输出格式支持情况 |
| `PUT /scopes/{scope_id}/sessions/{session_id}` | 幂等登记经 emu-chat 验证的会话映射，不接受浏览器直连 |
| `POST /scopes/{scope_id}/uploads` | 单文件流式上传，带上传幂等键；校验后返回资源元数据 |
| `GET /scopes/{scope_id}/assets/{asset_id}` | 有权限的元数据、状态和可执行操作 |
| `GET /scopes/{scope_id}/assets/{asset_id}/content` | 稳定、可重复读取的原文件；可另设 thumbnail 变体 |
| `PUT /scopes/{scope_id}/submissions/{operation_id}` | 幂等绑定有序附件、目标会话和输入摘要；同 ID 不同内容返回冲突 |
| `GET /scopes/{scope_id}/assets` | 分页查询，支持按 operation、session、tool_call 过滤，不返回其他会话资源 |
| `POST /scopes/{scope_id}/reconcile` | 从已登记会话的公开权威历史补偿图片与消息关联，只做采集，不执行模型 |
| `POST /scopes/{scope_id}/assets/{asset_id}/retry-capture` | 重试已知来源的采集；不接受客户端任意 URL 或路径 |
| `PUT /scopes/{scope_id}/references/{reference_id}` | 幂等维护草稿、队列、历史/分支等引用集合，以 revision 拒绝迟到覆盖 |
| `DELETE /scopes/{scope_id}/references/{reference_id}` | 幂等释放指定引用 |
| `DELETE /scopes/{scope_id}` | 持久化删除意图、撤销该范围引用和访问，重试安全；物理清理另行完成 |

emu-chat 暴露对应的 `/api/conversations/{id}/media/...` 接口，不开放通用代理。它先验证本地会话存在、未待删除及资源关系，再以服务端凭据访问插件。前端历史对象的 `attachments` 含资源 ID、来源、状态、尺寸及同源路径，不含宿主绝对路径、远端签名 URL 和 Base64。

插件可用时，新建/打开 emu-chat 会话即幂等登记 scope 与 Hermes session，而不是等第一张上传后才登记，这样纯文字触发的生图也能被采集。已有会话按实际访问登记，不批量导入其他客户端会话。附件提交必须确认登记成功；纯文字聊天遇到插件故障仍按原链路运行，不能为图片能力新增硬性派发前置条件。故障期间产生的结果在后续访问时尝试有界历史补偿，不承诺来源失效后仍可追回。

现有 `/v1/toolsets` 的 enabled/configured 只表示配置，不代表供应商实际可用。能力探测不执行付费调用。分别报告 `available`、`unsupported`、`unconfigured`、`unknown`，附简短原因；插件缺失只降低图片能力，不使文字聊天的 Hermes 健康检查失败。

### 鉴权与 I/O

- 当前生产 Hermes 的新路由不会自动经过原生 handler 内的 `_check_auth`。插件使用自己的 Bearer 密钥 `EMU_MEDIA_API_KEY`，在 Hermes 插件和 emu-chat 服务端各配置一次，常量时间比较、缺失则关闭路由；浏览器不得收到该密钥。不要依赖或调用 Hermes 私有鉴权方法。
- 不要求更改 systemd 运行结构或新增端口。复用 Hermes API listener；插件自己的密钥不授予 Hermes 核心 API 权限。插件需要读公开会话 API 时使用单独的、现有 Hermes 服务端凭据，不能混淆两种认证。
- 只为上传路由增加二进制 body limit，保留普通 JSON 的 128 KiB 上限。上游当前总请求限制是 10,000,000 字节，因此每次上传只传一张不超过 8 MiB 的图片，计入 multipart 开销；不把四张图合成一个巨大 JSON。
- 上传、原图读取、结果下载逐块限流计数，设置连接/空闲/总时限并传播取消，不能先完整读入内存再检查。复用现有 JSON 4 MiB 读取路径会误伤图片，必须分开。
- 文件名仅作为下载展示信息；实际存储名由服务生成。校验 magic bytes、解码、像素、尺寸与 MIME；不使用用户提供路径。响应固定真实图片 MIME、nosniff，私有缓存/ETag 按引用撤销策略设置，不使用公共 CDN 缓存。
- 采集只接受已识别图片工具结果里的受支持来源。下载远端输出防止私网/回环/链路本地访问及重定向绕过，限制域名/IP、协议、次数和大小；不提供接受任意 URL 的下载接口。复制本地输出必须限制到明确允许的图片输出目录，处理 symlink、路径穿越与文件替换，拒绝凭据和任意宿主文件。
- 默认总存储预算 5 GiB，可配置并计入临时/预留空间；容量不足拒绝新上传或将采集标记失败，不自动淘汰被引用图片。不在日志记录图片内容、Base64、密钥或完整签名 URL。
- emu-chat 沿用当前单用户访问控制边界；插件鉴权只是服务间隔离，不能宣称给前端增加了登录保护。

## 5. 输入桥接与 Run 约定

继续调用 `/v1/runs`，保留原来的运行、幂等、停止和审批能力。首版基线为“文字＋可持久化附件清单＋原有图片工具”，不依赖主聊天模型原生视觉。

派发前先确认图片就绪及会话引用，登记 operation，再冻结实际提交的 Run 请求。附加清单包含版本、operation ID 和有序 asset ID，使用严格结构、明确边界；资源权限由插件已登记的绑定确认，不能仅凭模型或用户写出的清单获得读取权限。原始用户文字保持不变，默认纯图片识图提示及机器清单分别标识。

机器清单随 Hermes 用户消息持久化，历史读取据此定位输入附件，避免队列载荷清理后失去关联。emu-chat 仅在后台验证其与已登记 operation、输入摘要、会话相符后把清单转换成附件；不能用宽泛正则删除用户原文。缺乏证明则显示原始内容或待核对状态。后台长期保留的是摘要与引用，完整用户正文仍以 Hermes 为准。

插件通过官方 `pre_llm_call` 注入当前已验证附件的可用说明；通过文档化的 `pre_tool_call` 对受管理引用进行验证/必要转换，范围仅限 `vision_analyze` 与 `image_generate` 的图片参数。不得拦截其他工具、替换模型服务或从结果 Hook 修改执行行为。给模型的资源表示必须可以用来选择某张图，不能要求模型猜浏览器 URL。

P0 需在实际配置的工具/terminal backend 上确定输入表示：优先使用允许目录中的工具可读暂存文件；供应商只接受 URL/data 时，仅在工具调用边界转换已授权图片。这些转换属于传输适配，不实现新的供应商协议。不能把需要 Bearer 的浏览器资源 URL 直接交给无法认证的第三方模型，也不能靠公开图片服务绕过。

必须证明转换后的大段 Base64 不会进入长期历史或普通日志；若官方 Hook 路径做不到，使用已验证的暂存文件路径，或在 P0 明确该组合不支持。不得以导入 Hermes 私有图片解析器或 monkeypatch 作为隐含后门。具体桥接方式是待实测的工程事实，不需要用户选择。

同一队列项重试使用相同的冻结 Run body、附件顺序和幂等键。更改插件模板、有效会话映射或附件内容都不能静默改写已经尝试提交的请求。模型供应商内部是否恰好执行一次不受本项目控制；本项目保证不因前端/采集重试主动再发一份生成请求。

## 6. 输出采集与故障恢复

`post_tool_call` 仅处理已登记会话/turn 的 `image_generate` 结果，检查 Hook 状态和工具业务 success/error。先用短事务保存来源和待采集记录，再由后台 I/O worker 下载/复制和验证文件；不要在 Hook 内下载大图或阻塞 agent 线程。

幂等来源键至少含实际会话 ID、tool_call_id 和输出序号；turn ID 辅助关联，不用工具名或时间戳替代。缺少调用 ID 的候选记录隔离为待核对，拿到历史消息身份后再确定。URL、`image`、`host_image`、`agent_visible_image` 按明确格式适配，后两者可能指同一张图，不能重复展示。只采集工具实际返回的结果，不按 `images_generated` 数字臆造资源；当前部分路径只返回第一张图片。

建议资源可用状态：`pending` → `ready` / `capture_failed`，删除另有 `deleting/deleted`。输入上传的 `uploading` 是浏览器/传输状态，只有原文件验证并持久化成功才发放可用于发送的 ready 资源。每个输出独立记录状态，一次调用多个输出时允许部分成功。

原文件落盘使用临时文件与原子 rename，索引记录摘要、MIME、尺寸、字节数和真实存在状态；崩溃留下的临时文件可回收，不能产生数据库 ready 但文件不存在的成功承诺。原文件成功即允许读取，缩略图失败不应阻止下载原图。

重启扫描未完成采集，重试使用同一来源键。Hook 是 fail-open，记录都没写入时，要从受登记会话的公开历史接口补偿；实时 tool.completed、Run 终态、打开历史及重启后的待核对 scope 都可触发有界对账。合并重复任务、分页读取、使用水位并适量回看，不反复扫描全部会话。

对账请求不接收浏览器提供的任意工具输出。插件通过公开 Hermes 历史接口读取并核实来源，或由可信 emu-chat 后端提供带明确消息身份的已核实记录；P0 选择一种并固定，本规格优先插件读取公开接口。禁止直接操作 Hermes SessionDB。

前端分别展示“工具执行中”“图片保存中”“可查看”“图片保存失败”。只有 ready 才提供稳定预览/下载/再次引用。采集失败保留来源与错误，允许“重试保存”；来源已过期且无可读本地文件时明确提示无法恢复，重新生成必须是用户新提交的消息。

## 7. emu-chat 草稿、队列与历史

- 草稿 content 与有序 attachment refs 共用 revision，并原子保存。上传完成的晚回调不能覆盖用户刚移除的附件，切换会话后只能回写原 scope；会话已删除则停止绑定并进入孤儿清理。
- 发送在已有事务中冻结文字和引用集合、生成 payload hash、创建队列项并清空对应草稿快照。hash 包含结构版本、文字、有序 asset ID/内容标识；不能只 hash 文字。至少文字或一张 ready 图片存在才允许发送。
- 任一附件尚未上传完成或未就绪时禁止发送整个草稿，保留失败图片和文字；用户可移除失败附件或重试，不静默发送缺图消息。刷新后恢复已完成且保存的引用；浏览器尚未上传完成的原始 File 不承诺刷新后恢复，也不能显示已保存。
- 队列列表、队列编辑、copy-to-draft、覆盖非空草稿确认、取消、失败保留和到期清理都扩展到附件。只含图片的草稿也算非空。发送响应不能覆盖发送期间用户新输入的文字或新附件。
- 跨服务登记/引用同步使用本地持久化 outbox 或等价控制记录，不能把远端 HTTP 放进 SQLite 事务。先获得引用保护再提交 Run；无法确认保护时不派发。失败重试幂等，释放先撤销本地可见性再异步清理远端。
- Run 已接收但响应丢失时按现有幂等/对账恢复；不重新上传所有图片，不生成新 operation。历史附件与乐观消息交接使用 operation/消息身份，改掉图片路径上“相同正文就是同一消息”的判断。
- SSE 只通知刷新，权威消息＋插件资源索引决定最终附件归属。历史分页、重复事件和迟到响应不能重复出图或跨会话挂图。不要解析 SSE 的 500 字符预览提取最终 URL。
- 队列正文和控制记录到期前，已提交输入必须具有历史引用，失败输入必须仍有恢复引用；无法确认历史引用时延后释放。历史图片不跟随 7 天队列控制记录自动清除。
- 插件资源列表只是按当前会话/已加载消息补充信息，不变成第二套聊天历史。首次接入不回扫其他客户端的全部历史。

## 8. 会话分支、删除与图片保留

用户已确认：图片随会话保留，最后一个引用删除后清理；没有独立图库，已进入历史或仍在有效草稿/队列中的图片不按时间自动到期。

- 删除确认中明确说明将清理本会话独占图片，沿用现有不可逆删除的勾选确认，不额外增加第二个确认流程。其他会话/分支仍使用的图保留。
- 最后一个引用释放后先撤销该 scope 访问，物理清理保留默认 24 小时宽限，用于跨服务对账与崩溃恢复；这不是向用户提供的回收站。未完成绑定的上传、显式移除的未发送附件和临时文件适用有界孤儿回收。
- 上传成功后获得临时引用保护，只有后台确认未进入草稿、队列或历史才可在宽限期后回收。emu-chat 离线或引用同步状态未知时延后回收，不把“暂时查不到”当成无引用。已保存的草稿不因用户几天未访问而失效。
- 分支只继承实际复制消息引用的图片，按公开分支响应和权威消息身份建立新 scope 引用；不能复制整个源会话未来消息的图片，也不能依赖 Fork 保持原 message ID。映射未完成标记待核对，阻止误清理相关资源。
- 会话压缩/有效 ID 变化时登记别名，保留历史原 ID。Hook 看到新 ID 但尚未关联时保留待核对，不直接归到别的最近会话。
- 删除先持久化意图并阻止新发送/上传/引用；沿用当前会话删除的确认与上游删除对账。资源引用释放必须有可重试记录，不能随本地 conversations 行级联消失而漏清理。
- 上传或结果采集与删除并发时，scope tombstone 阻止迟到写入使图片复活；重试删除幂等。正常 UI 撤销访问先于物理 unlink，未完成的删除可在重启后继续。
- 垃圾回收要检查草稿、队列、历史、分支和待关联记录；对状态不确定的资源保守保留并可观测，不能因为一次上游超时/404 就删除文件。

## 9. 前端交互

- 输入区新增紧凑上传入口与附件缩略图；拖放只在明确区域接收文件。粘贴图片时保留正常文本粘贴，上传错误定位到具体附件。
- 附件预览可移除，上传中显示进度或不确定进度，不伪造精确百分比。失败可重试；引用未就绪时不能发送。
- 用户消息展示输入图片，助手工具结果卡片附近展示生成图片；不展开原始工具 JSON 才能看到图。已有工具过程和回答顺序保持，未知归属显示待核对而不是猜位置。
- 点击大图进入单实例查看器，支持适应窗口、缩放、下载、关闭；透明图有棋盘背景，移动端可返回，键盘可关闭且焦点返回触发项。
- “用于下一条消息”把图片加到当前所属会话的草稿并聚焦输入框，不自动发送、不自动删除已有附件/文字；达到上限明确提示。跨会话复用首版可用下载再上传，内部数据模型仍须支持分支共享引用。
- 新编辑结果不覆盖正在查看的旧图，也不自动弹出查看器；切换/删除会话关闭旧查看器、释放 object URL，不丢草稿。
- 插件缺失/不兼容时禁用新图片操作并提供简短原因，保留已有附件占位和草稿；普通文字会话仍能使用。带不可用附件的草稿不能静默丢图发送。

## 11. 验证与发版

遵循项目测试策略，保留少量有价值的自动化：附件 CAS/并发晚回调；完整请求幂等；跨服务引用与删除恢复；工具完成到采集的崩溃窗口；历史分页与会话身份交接。使用固定图片、受控 HTTP 源和模拟工具结果，避免把每个 CRUD/按钮写成测试或依赖付费模型质量。

真实浏览器检查桌面和移动端上传、粘贴、下载、查看器、重复点击发送及跨会话竞态。插件测试额外覆盖鉴权、路径限制、远端下载边界和尺寸上限，因为它们决定文件可读取范围。

emu-chat 实施后运行类型检查、Lint、构建及对应主干测试；按项目格式要求检查 Markdown。Hermes 插件使用独立测试环境和实际生产基线验证公开扩展契约，不改生产配置做实验。

发版保留现有目录和 systemd 结构：先安装固定提交的插件并配置服务端密钥，验证资源能力；再发布包含增量迁移的 emu-chat 版本。记录 Hermes、插件、emu-chat 三个提交。发布不等于让开发仓库直接成为生产运行目录。

升级/回退前取得一致的数据库与文件备份，范围包括 emu-chat 控制数据、Hermes 会话/配置、插件索引与文件；确认备份工具是否包含自定义持久目录。固定插件提交，官方更新不覆盖插件代码目录的前提仍需实测；恢复时兼顾代码、依赖、schema 和引用一致性，不能仅 git checkout 就宣称完成回退。

实施时更新 README、docs/02-data-model.md、docs/05-hermes-integration.md、docs/06-client-internals.md、docs/07-data-flow.md、docs/08-api-reference.md、docs/09-error-and-security.md 中受影响的现状说明，纠正 AGENTS.md 的部署前提。提案阶段不把未来接口写进现状文档。
