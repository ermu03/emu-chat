# 代码评审

根据用户给出的范围评审；未指定比较基点时检查当前工作树，包括暂存、未暂存及相关未跟踪文件。指定提交或分支时用合适的 Git diff 比较，不预设必须有 PR、Issue 编号或双代理。

先读 AGENTS.md、用户要求，以及相关的 ISSUES.md 条目、规格、系统文档和活跃决策笔记。按两条线检查：

1. 行为与需求：功能是否完整，错误路径、竞态、数据一致性、Hermes 契约和前后端 Schema 是否正确。
2. 项目约定：是否遵守必要测试范围、文档与决策笔记规则，是否引入无实际用途的抽象或偏离用户要求。

只报告有具体证据、会影响正确性或维护的发现。按严重程度排序，每项给出文件与行号、可复现依据或推理、影响及建议；不要把个人风格偏好当作缺陷。需要时运行针对性检查来核实疑点，避免为评审机械地跑完整套件。

评审本身只输出结果；若没有发现，说明检查范围及仍未验证的风险。需要修复时由用户要求或实现任务承接。
