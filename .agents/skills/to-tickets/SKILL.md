# 拆分实施任务

先读相关规格或 ISSUES.md 条目，再核对涉及的代码、AGENTS.md 和已有决策笔记。沿用现有条目，不为同一需求另建一套 Issue。

- 只有工作确实需要分阶段交付或跨会话接续时才拆分；小改动保留为一项。
- 每项任务写明可观察的完成结果。依赖关系只记录真正阻塞后续工作的前置任务，不强制把前端、后端、数据库和测试拆开或全部纳入每一项。
- 在 ISSUES.md 对应条目下添加简短待办清单；需要较长背景时链接 .agents/specs/ 中的规格。不要复制决策笔记全文。
- 已有任务完成时更新原清单，不另建重复条目。验收与测试要求遵守 AGENTS.md。
- 用户明确要求使用外部跟踪器时再按其指示处理；本项目默认只维护本地 ISSUES.md。

输出拆分依据和下一项可开始的工作。对能从现有资料判断的粒度和顺序自行决定。
