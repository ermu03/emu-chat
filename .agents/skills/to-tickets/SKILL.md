# 拆分实施任务

先读相关规格或 .agents/notes/proposed/ 笔记，再核对涉及的代码、AGENTS.md 和同主题决定。已有提案就沿用；需要跨会话跟进而尚无提案时，按 docs/decision-notes.md 新建一篇，不另建待办清单。

- 只有工作确实需要分阶段交付或跨会话接续时才拆分；小改动保留为一项。
- 每项任务写明可观察的完成结果。依赖关系只记录真正阻塞后续工作的前置任务，不强制把前端、后端、数据库和测试拆开或全部纳入每一项。
- 在原提案的 Proposal 下补充简短实施步骤；Acceptance criteria 仍写可观察结果。需要较长背景时链接 .agents/specs/ 中的规格，不复制整篇笔记。
- 只有独立目标确实需要分别流转状态时才拆成多篇 proposed，并在笔记间链接；完成步骤时更新原提案，整体完成后按 docs/decision-notes.md 流转。
- 用户明确要求使用外部跟踪器时再按其指示处理；本项目默认以 proposed 笔记承接待处理事项。验收与测试要求遵守 AGENTS.md。

输出拆分依据和下一项可开始的工作。对能从现有资料判断的粒度和顺序自行决定。
